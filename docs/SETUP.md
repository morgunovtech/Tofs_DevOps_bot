# Как запустить TofsDevOps на Railway — простая инструкция

Эта инструкция для тех, кто не хочет возиться с серверами. Никакого терминала, SSH и Docker-команд: всё делается мышкой в браузере. Займёт 10 минут.

**Что получится в итоге:** у тебя в Telegram появится личный бот, который круглосуточно следит за твоими сайтами и пишет только тогда, когда что-то сломалось (и каждое утро — короткое «✅ всё в порядке»).

**Что понадобится:**
1. Аккаунт в Telegram (уже есть).
2. Аккаунт на [Railway](https://railway.com) — это хостинг, который сам собирает и запускает бота. Войти можно через Google, GitHub или почту. Первые 30 дней Railway даёт $5 и не просит карту. Потом нужен тариф Hobby — $5 в месяц, и в эти $5 уже входит потребление ресурсов, боту хватает. Без Hobby аккаунт переходит на бесплатный план с $1 в месяц, а боту нужно около $2: он остановится, и никто не напишет, а через 30 дней Railway удалит диск с базой. Для оплаты нужна карта, которой можно платить за рубежом: российские не подойдут. Нет карты — бота можно бесплатно поставить на свой сервер через Docker ([README](../README.ru.md#бесплатно-свой-сервер-через-docker)).

## Шаг 1. Создать бота в Telegram (2 минуты)

1. Открой Telegram и найди в поиске **@BotFather** (официальный бот с синей галочкой).
2. Нажми **Start** (или напиши `/start`).
3. Отправь ему команду:
   ```
   /newbot
   ```
4. BotFather спросит имя — напиши любое, например `Мой DevOps`.
5. Потом спросит username — он должен заканчиваться на `bot`, например `moy_devops_bot`. Если занято — попробуй другой.
6. В ответ придёт сообщение с **токеном** — длинная строка вида `1234567890:AAEhBOweik6ad9r_QXMENQjcrGbqCr5yLYE`.

**Скопируй этот токен** — он понадобится на Шаге 2. Никому его не показывай: у кого токен — у того и бот.

---

## Шаг 2. Развернуть бота в одну кнопку (3 минуты)

[![Deploy on Railway](https://railway.com/button.svg)](https://railway.com/deploy/lVRuwW)

1. Нажми кнопку выше и войди в Railway (через Google, GitHub или почту).
2. Railway покажет одно поле — **TELEGRAM_BOT_TOKEN**. Вставь туда токен из Шага 1.
3. Нажми **Deploy**. Всё остальное уже настроено в шаблоне: диск для базы (`/app/data`), адрес в интернете, нужные переменные. Сборка займёт пару минут — дождись у сервиса статуса **Online**.

Секреты (`WEBHOOK_SECRET`, `HEARTBEAT_SECRET`) задавать не нужно: бот сгенерирует их сам при первом старте и покажет в **⚙️ Настройки → 🔌 Подключения**.

<details>
<summary>Хочешь свою копию кода на GitHub и всё настроить руками? Так тоже можно</summary>

**1. Свою копию кода на GitHub.**

1. Зарегистрируйся на [github.com](https://github.com), если аккаунта ещё нет.
2. Открой страницу бота: **github.com/morgunovtech/Tofs_DevOps_bot**.
3. Нажми кнопку **Fork** (справа вверху) → **Create fork**.

Теперь у тебя есть собственная копия кода — Railway будет запускать именно её, а обновлять её можно в один клик (см. «Как обновлять бота» внизу).

**2. Развернуть её на Railway.**

1. Зайди на [railway.com](https://railway.com) и войди через GitHub (**Login → GitHub**).
2. Нажми **New Project → Deploy from GitHub repo** и выбери свой форк `Tofs_DevOps_bot`. Если Railway попросит доступ к репозиториям — разреши (Configure GitHub App).
3. Railway сам найдёт `Dockerfile` и начнёт сборку. Пока она идёт — настроим переменные.
4. Открой созданный сервис → вкладка **Variables** → **New Variable** и добавь по одной:

   | Переменная | Значение |
   |---|---|
   | `TELEGRAM_BOT_TOKEN` | токен из Шага 1 |
   | `DB_PATH` | `/app/data/bot.db` |
   | `TIMEZONE` | твой часовой пояс, например `Europe/Moscow` (необязательно: это значение по умолчанию, и его можно поменять в боте) |

   Секреты (`WEBHOOK_SECRET`, `HEARTBEAT_SECRET`) задавать не нужно: бот сгенерирует их сам при первом старте и покажет в **⚙️ Настройки → 🔌 Подключения**.

5. **Подключи диск для базы данных** — обязательно: без него при каждом обновлении бот забывает сайты, настройки и тебя как хозяина (если забудешь, бот сам напишет об этом после /start и в ⚙️ Настройки → 🔌 Подключения): правый клик по сервису (или меню ⋮) → **Attach Volume** → в поле Mount Path введи:
   ```
   /app/data
   ```
6. **Открой бота в интернет** (нужно для heartbeat-«отметок» и виджета обратной связи): вкладка **Settings → Networking → Generate Domain**. Railway спросит порт — введи **8080**. Получишь адрес вида `https://твоё-имя.up.railway.app`; бот подхватит его сам, переменная `PUBLIC_BASE_URL` не нужна.
7. Там же в **Variables** добавь `TRUST_PROXY=1`: Railway стоит перед ботом как прокси, и без этого все посетители виджета выглядят одним адресом.

8. Railway передеплоит сервис после изменения переменных (или нажми **Deploy**, если предложит). Дождись статуса **Active**. Проверить, что всё хорошо: вкладка **Deployments → View Logs** — там должна быть строка `Bot started: @имя_твоего_бота`.

## Шаг 3. Познакомиться с ботом

1. Открой Telegram, найди своего бота по username из Шага 1 (например, `@moy_devops_bot`).
2. Нажми **Start**.
3. Бот ответит: «🔑 Ты стал администратором» — с этого момента бот слушается только тебя.
4. Нажми кнопку **«➕ Добавить первый сайт»** и отправь адрес своего сайта, например:
   ```
   mysite.com
   ```
5. Бот сразу проверит сайт и ответит что-то вроде: «✅ mysite.com под присмотром. ✅ Открывается за 0.12 с. 🔒 Сертификат безопасности действует ещё 77 дн.»

## Шаг 4. Последние шаги — не пропускай (3 минуты)

Бот молчит, когда всё хорошо. Чтобы его молчание и правда значило «всё хорошо», после первого сайта он сам предложит последние шаги:

1. **🔔 Пробная тревога.** Через минуту бот пришлёт тревогу — такую же, как «сайт лёг». Сверни Telegram везде (на телефоне и на компьютере) и жди звонка. Не зазвонило — бот подскажет, что поправить: чаще всего выключен звук у чата. Иначе настоящая тревога тоже придёт без звука.
2. **🛡 Сторож.** Если сломается сам бот, он тоже замолчит — и это будет выглядеть как «всё хорошо». Сторож следит за ботом снаружи: зарегистрируйся на [healthchecks.io](https://healthchecks.io) (бесплатно), создай «check» с периодом 5 минут и скопируй ссылку вида `https://hc-ping.com/длинный-код`. В боте нажми **🛡 Подключить сторожа** → **🔗 Вставить ссылку** — бот проверит, что check существует, и сохранит. Дальше бот выходит с ним на связь каждые 5 минут; пропадёт — healthchecks напишет тебе на почту. Состояние сторожа видно на главном экране и в утренней сводке. (Переменная `SELF_HEARTBEAT_URL` в Railway по-прежнему работает как запасной вариант.)
3. **💳 Тариф Railway.** Бот не видит, на каком ты тарифе, поэтому спрашивает: пробный период — 30 дней, потом без Hobby он остановится. Перешёл на Hobby (или он уже был) — нажми **✅ Уже на Hobby**, и бот больше не спросит. Не нажал — он напомнит ещё раз примерно на 25-й день.

Пропустил — ничего страшного: пробная тревога есть в ⚙️ Настройки → 🔔 Когда писать, сторож и тариф Railway — в ⚙️ Настройки → 🔌 Подключения, а утренняя сводка напоминает о стороже, пока его нет.

**Всё, настройка закончена.** Дальше бот работает сам:
- проверяет сайты каждые 5 минут;
- молчит, пока всё хорошо;
- каждое утро в 9:00 присылает короткую сводку;
- если сайт упадёт — напишет сразу (и сначала перепроверит с других серверов, чтобы не тревожить зря);
- если сам был выключен дольше 10 минут — скажет, когда его не было, а пропущенную утреннюю сводку пришлёт с опозданием;
- если Telegram не принял сообщение — повторит его, как только сможет, с пометкой, когда оно должно было прийти.

## Полезные мелочи (по желанию, в любой момент)

Всё ниже — опционально. Бот полноценно работает и без этого.

**Поменять время сводок, включить «тихие часы», выбрать часовой пояс**
🏠 Главная → ⚙️ Настройки → 🔔 Когда писать. Пара тапов, без правки файлов. Там же переключатель «🔔 Будить: только «сайт лёг»» — если ночью хочешь просыпаться только от настоящего падения.

**Чтобы о падении узнал кто-то ещё**
⚙️ Настройки → 👥 Помощники → 🔗 Пригласить — перешли ссылку коллеге или другу. Он будет получать только тревоги «сайт лёг» и «снова работает», без возможности что-то менять. Пригодится, когда ты в отпуске.

**Следить, что бэкапы и другие боты реально работают**
Если где-то (на другом сервере, в CI) у тебя есть задачи по расписанию — бэкапы и т.п. — или другой бот:
1. В боте: 🏠 Главная → «🤖 Боты» → «➕ Бот или задача». Бот спросит, что это — бот или задача по расписанию, — и покажет адрес и готовую строку именно для твоего случая (у SocialBot адрес вставляется в переменную `HEALTHCHECK_URL`).
2. Задача появится на главном экране рядом с сайтами. Если она замолчит — бот заметит и скажет.

**Узнать, сколько реально ждут твои посетители**
🔌 Подключения → ⚡ Скорость у посетителей Chrome: нужен бесплатный ключ Google, бот проведёт по шагам. На сайты ничего ставить не нужно. На карточке появится, за сколько у посетителей появляется страница и как быстро откликаются кнопки — для сайтов, у которых достаточно посетителей в Chrome; у небольших сайтов Google данных часто не собирает.

**Перенести бота или вернуть базу**
Ничего нажимать не нужно: каждую ночь бот делает копию своей базы, а по воскресеньям присылает её файлом в чат. Свежую копию прямо сейчас — 🏠 Главная → «🤖 Боты» → **💾 Скачать копию базы**. Чтобы восстановить (или перенести бота на новый сервер) — просто пришли этот файл боту: он узнает свою копию и переспросит, прежде чем заменить базу. В копии есть токены подключений — храни её как пароль.

**Виджет обратной связи («нашли опечатку?»)**

Чтобы посетители сайта могли одной кнопкой сообщить о проблеме или опечатке прямо тебе в Telegram:

1. В боте: ⚙️ Настройки → **📩 Обратная связь** — внизу экрана лежит готовый сниппет с твоим адресом и секретом. Вставь его на сайт перед `</body>`:
   ```html
   <script>window.DevOpsFeedback = {
     webhookUrl: 'https://твоё-имя.up.railway.app/api/feedback',
     secret: 'секрет-из-диагностики',
     button: false            // true — плавающая кнопка «⚠️ Проблема?»
   };</script>
   <script src="https://твоё-имя.up.railway.app/feedback-widget.js"></script>
   ```
2. Любой ссылке, которая должна открывать форму, добавь атрибут `data-devops-feedback`:
   ```html
   <a href="#" data-devops-feedback>нашли опечатку?</a>
   ```
   Если посетитель выделил текст на странице, он подставится в форму сам.
3. Сообщение прилетит в Telegram («📩 Сообщение с сайта … Страница: …») и останется в списке 📩 Обратная связь.

Если на сайте настроен строгий Content-Security-Policy (например, `script-src 'self'; connect-src 'self'`), добавь адрес бота в `script-src` и `connect-src` — или положи `feedback-widget.js` к себе на сайт и разреши только `connect-src`.

**Публичная статус-страница**
В боте: ⚙️ Настройки → **🌐 Статус-страница** → **Включить** — и по адресу `https://твоё-имя.up.railway.app/status` появится страница «всё ли работает» с аптаймом, которую можно отправить кому угодно. Хочешь, чтобы адрес нельзя было угадать — там же **🔑 Сделать ссылку секретной**: страница переедет на `/status/<секрет>`, а без него будет отвечать «не найдено». (Переменная `STATUS_PAGE_SLUG` тоже работает.)

**Следить за главной функцией сайта (API)**
Мало знать, что главная открывается, — важно, что работает то, ради чего сайт сделан: проверка пароля, поиск, оплата. Для этого добавь адрес API как ещё один сайт:

1. 🏠 Главная → «🌐 Сайты» → «➕ Добавить сайт» → пришли адрес вместе с путём, например `good-pass.pages.dev/api/v1/analyze`. Адрес под `/api/` (или на домене `api.…`) бот сохраняет с путём и считает **API-проверкой**: следит только за ответом — код, время, фраза в ответе. Поиск, ссылки и SEO у API не проверяются (иначе GET на POST-эндпоинт выглядел бы как «сайт лежит»), а сертификат и домен остаются на карточке самого сайта — тревога о них придёт одна, а не две.
2. Если API ждёт POST: в ответе бота нажми **📡 Настроить запрос** → «📡 Метод» → POST, «📡 Тело» → например `{"password":"Tr0ub4dor&3"}` (JSON уходит с `Content-Type: application/json` сам), при необходимости «📡 Заголовки» (`Authorization: Bearer …`).
3. «🔍 Фраза» → «должна быть» → слово, без которого ответ неправильный, например `scoreLabel`. Так бот заметит и «HTTP 200, а внутри ошибка».

Любой метод, кроме GET и HEAD, тоже делает проверку API-проверкой — даже без `/api/` в адресе. Файл экспорта из прежних версий (JSON с полями `http_method`, `http_body`, `http_headers`, `keyword` у сайта) по-прежнему можно прислать боту в чат — он добавит из него сайты.

**Порядок в GitHub — раз в неделю**
Если твои сайты живут в GitHub, бот может по воскресеньям говорить, что там пора прибрать: PR, которые висят дольше недели, лишние ветки, выключенное удаление веток после мержа, красный CI на основной ветке, репозитории, которые пропали с прошлой недели, уязвимости от Dependabot. Когда всё в порядке — ни строчки.

1. GitHub → Settings → Developer settings → **Fine-grained tokens → [Generate new token](https://github.com/settings/personal-access-tokens/new)**. Срок — какой удобно (когда токен истечёт, бот так и скажет в отчёте).
2. **Repository access → All repositories** (или выбери нужные). Для репозиториев организации выбери её в **Resource owner**.
3. **Permissions → Repository permissions**, везде **Read-only**: **Metadata** (обязательно), **Contents** (ветки), **Pull requests**, **Commit statuses** (статус CI); по желанию **Dependabot alerts** — без него строки про уязвимости просто не будет. Отдельного права «Checks» у таких токенов нет: результаты GitHub Actions публичных репозиториев видны и так; если для приватного репозитория статус CI не прочитается, бот о нём промолчит, а не соврёт.
4. В боте: ⚙️ Настройки → 🔌 Подключения → ➕ Подключить ещё → **🐙 Подключить GitHub** → «🔑 Ввести токен». Бот проверит токен живым запросом и удалит сообщение с ним. Репозитории организации или чужого аккаунта — «👤 Чьи репозитории».

Вместо чата можно задать переменные `GITHUB_TOKEN` и `GITHUB_OWNER` (необязательная: по умолчанию — владелец токена) в Railway → Variables.

**Google, Яндекс, Cloudflare** — подключаются прямо из бота: ⚙️ Настройки → **🔌 Подключения** → кнопка у нужного пункта. Бот покажет два-три шага, примет токен или JSON-ключ сообщением, проверит его живым запросом и сохранит в своей базе. Переменные в `.env` для этого больше не нужны, но по-прежнему работают как запасной вариант (все они описаны в [.env.example](../.env.example)).

> **Чего на Railway не будет:** функций, которым нужен доступ к Docker на твоём собственном сервере — автоперезапуска *других* контейнеров и автоочистки диска (`AUTORESTART_CONTAINERS`, `AUTO_CLEANUP`). Они нужны только при самостоятельном хостинге на VPS и на Railway просто тихо отключаются, всё остальное работает полностью.

## Если что-то пошло не так

1. **Первым делом** — в боте: 🏠 Главная (кнопка под полем ввода) → ⚙️ Настройки → **🔌 Подключения**. Бот сам проверит свои части, а у каждого не-зелёного пункта будет кнопка с решением.
2. Посмотреть логи: в Railway открой сервис → **Deployments → View Logs**.
3. Перезапустить бота: меню ⋮ у сервиса → **Restart**.
4. Бот не отвечает на /start — проверь в **Variables**, что токен вставлен целиком и без пробелов, и что деплой в статусе **Active**.

## Как обновлять бота

**Код бота.** Когда выйдет новая версия:

- **Развернул кнопкой.** Railway сам проверяет, не обновился ли шаблон, и предлагает обновление в проекте — согласись, и бот передеплоится. Хочешь управлять кодом сам — в сервисе **Settings → Source → Eject**: Railway сделает копию кода у тебя на GitHub, дальше как с форком.
- **Развернул из своего форка.** Открой форк на GitHub — вверху появится плашка «This branch is N commits behind». Нажми **Sync fork → Update branch**, и Railway передеплоит бота сам.

Все твои сайты и настройки сохранятся — они живут в базе данных на подключённом диске, а не в коде.

**Библиотеки, из которых бот собран, обновляются сами** — в исходном репозитории, а оттуда приходят вместе с новой версией. В твоём форке (если он есть) работает то же самое: в репозитории уже лежат три файла, которые это делают:

- `.github/dependabot.yml` — GitHub раз в неделю (по субботам) сам открывает pull request с обновлениями всех библиотек;
- `.github/workflows/ci.yml` — на этот PR автоматически запускаются проверки: линтер, ~150 тестов и `pip-audit` (поиск известных уязвимостей);
- `.github/workflows/dependabot-automerge.yml` — сам дожидается этих проверок и вливает PR, только если все зелёные (кроме крупных версий: их лучше глянуть глазами). Упали тесты — PR остаётся открытым, а бот в воскресном отчёте скажет, что он висит.

Railway увидит новый коммит в `main`, передеплоит бота, а бот при старте напишет тебе: «🔄 Бот обновился: aiohttp 3.10.11 → 3.14.3». Раз в неделю он ещё и сам сверяет свои пакеты с базой уязвимостей и скажет, если что-то небезопасно.

Настраивать в форке ничего не нужно: робот сам ждёт тестов и не вливает непроверенное. GitHub Actions в публичном репозитории бесплатны. (Правило ветки «Require status checks to pass» для `main` по-прежнему полезно — оно не даст влить красный PR и руками.)
