# Как запустить TofsDevOps на Railway — простая инструкция

Эта инструкция для тех, кто не хочет возиться с серверами. Никакого терминала, SSH и Docker-команд: всё делается мышкой в браузере. Займёт 10–15 минут.

**Что получится в итоге:** у тебя в Telegram появится личный бот, который круглосуточно следит за твоими сайтами и пишет только тогда, когда что-то сломалось (и каждое утро — короткое «✅ всё в порядке»).

**Что понадобится:**
1. Аккаунт в Telegram (уже есть).
2. Аккаунт на GitHub (бесплатно) — чтобы сделать свою копию бота.
3. Аккаунт на [Railway](https://railway.com) — это хостинг, который сам собирает и запускает бота из кода. Тариф Hobby стоит 5 $/мес, и в эти 5 $ уже входит потребление ресурсов — боту хватает с большим запасом.

---

## Шаг 1. Создать бота в Telegram (2 минуты)

1. Открой Telegram и найди в поиске **@BotFather** (официальный бот с синей галочкой).
2. Нажми **Start** (или напиши `/start`).
3. Отправь ему команду:
   ```
   /newbot
   ```
4. BotFather спросит имя — напиши любое, например `Мой DevOps`.
5. Потом спросит username — он должен заканчиваться на `bot`, например `moy_devops_bot`. Если занято — попробуй другой.
6. В ответ придёт сообщение с **токеном** — длинная строка вида `1234567890:AAEhBOweik6ad9r_QXMENQjcrGbqCr5yLYE`.

**Скопируй этот токен** — он понадобится на Шаге 3. Никому его не показывай: у кого токен — у того и бот.

---

## Шаг 2. Сделать свою копию бота на GitHub (1 минута)

1. Зарегистрируйся на [github.com](https://github.com), если аккаунта ещё нет.
2. Открой страницу бота: **github.com/morgunovtech/Tofs_DevOps_bot**.
3. Нажми кнопку **Fork** (справа вверху) → **Create fork**.

Теперь у тебя есть собственная копия кода — Railway будет запускать именно её, а обновлять её можно в один клик (см. «Как обновлять бота» внизу).

---

## Шаг 3. Развернуть на Railway (5 минут)

1. Зайди на [railway.com](https://railway.com) и войди через GitHub (**Login → GitHub**).
2. Нажми **New Project → Deploy from GitHub repo** и выбери свой форк `Tofs_DevOps_bot`. Если Railway попросит доступ к репозиториям — разреши (Configure GitHub App).
3. Railway сам найдёт `Dockerfile` и начнёт сборку. Пока она идёт — настроим переменные.
4. Открой созданный сервис → вкладка **Variables** → **New Variable** и добавь по одной:

   | Переменная | Значение |
   |---|---|
   | `TELEGRAM_BOT_TOKEN` | токен из Шага 1 |
   | `DB_PATH` | `/app/data/bot.db` |
   | `TIMEZONE` | твой часовой пояс, например `Europe/Moscow` (необязательно — это значение по умолчанию) |

   Секреты (`WEBHOOK_SECRET`, `HEARTBEAT_SECRET`) задавать не нужно: бот сгенерирует их сам при первом старте и покажет в **🩺 Диагностике**.

5. **Подключи диск для базы данных** (иначе история проверок будет стираться при каждом обновлении): правый клик по сервису (или меню ⋮) → **Attach Volume** → в поле Mount Path введи:
   ```
   /app/data
   ```
6. **Открой бота в интернет** (нужно для heartbeat-«отметок» и виджета обратной связи): вкладка **Settings → Networking → Generate Domain**. Railway спросит порт — введи **8080**. Получишь адрес вида `https://твоё-имя.up.railway.app`; бот подхватит его сам, переменная `PUBLIC_BASE_URL` не нужна.
7. Там же в **Variables** добавь `TRUST_PROXY=1`: Railway стоит перед ботом как прокси, и без этого все посетители виджета выглядят одним адресом.

8. Railway передеплоит сервис после изменения переменных (или нажми **Deploy**, если предложит). Дождись статуса **Active**. Проверить, что всё хорошо: вкладка **Deployments → View Logs** — там должна быть строка `Bot started: @имя_твоего_бота`.

---

## Шаг 4. Познакомиться с ботом

1. Открой Telegram, найди своего бота по username из Шага 1 (например, `@moy_devops_bot`).
2. Нажми **Start**.
3. Бот ответит: «🔑 Ты стал администратором» — с этого момента бот слушается только тебя.
4. Нажми кнопку **«➕ Добавить первый сайт»** и отправь адрес своего сайта, например:
   ```
   mysite.com
   ```
5. Бот сразу проверит сайт и ответит что-то вроде: «✅ mysite.com в мониторинге · Доступность: HTTP 200 (96ms) · SSL: 77 дн.»

**Всё, настройка закончена.** Дальше бот работает сам:
- проверяет сайты каждые 5 минут;
- молчит, пока всё хорошо;
- каждое утро в 9:00 присылает короткую сводку;
- если сайт упадёт — напишет сразу (и сначала перепроверит с других серверов, чтобы не тревожить зря).

Проверить, что уведомления доходят: **📱 Меню → ⚙️ Настройки → 🔔 Тест алерта**.

## Полезные мелочи (по желанию, в любой момент)

Всё ниже — опционально. Бот полноценно работает и без этого.

**Поменять время утренней сводки или включить «тихие часы»**
📱 Меню → ⚙️ Настройки. Пара тапов, без правки файлов.

**Следить, что бэкапы реально выполняются**
Если где-то (на другом сервере, в CI) у тебя есть задачи по расписанию — бэкапы и т.п.:
1. В боте: ⚙️ Настройки → ⏰ Контроль задач → ➕ — бот выдаст готовую строку-«отметку» с твоим Railway-адресом, которую нужно дописать в конец команды бэкапа.
2. Теперь если бэкап молча перестанет выполняться — бот заметит и скажет.

**Узнавать, если умрёт сам бот**
Зарегистрируйся на [healthchecks.io](https://healthchecks.io) (бесплатно), создай «check», скопируй ссылку вида `https://hc-ping.com/длинный-код` и добавь в Railway новую переменную:
```
SELF_HEARTBEAT_URL=https://hc-ping.com/твой-код
```
Бот будет отмечаться там каждые 5 минут; пропадёт — healthchecks пришлёт тебе письмо.

**Виджет обратной связи («нашли опечатку?»)**

Чтобы посетители сайта могли одной кнопкой сообщить о проблеме или опечатке прямо тебе в Telegram:

1. В боте: ⚙️ Настройки → **📩 Обратная связь** — внизу экрана лежит готовый сниппет с твоим адресом и секретом. Вставь его на сайт перед `</body>`:
   ```html
   <script>window.DevOpsFeedback = {
     webhookUrl: 'https://твоё-имя.up.railway.app/api/feedback',
     secret: 'секрет-из-диагностики',
     button: false            // true — плавающая кнопка «⚠️ Проблема?»
   };</script>
   <script src="https://твоё-имя.up.railway.app/feedback-widget.js"></script>
   ```
2. Любой ссылке, которая должна открывать форму, добавь атрибут `data-devops-feedback`:
   ```html
   <a href="#" data-devops-feedback>нашли опечатку?</a>
   ```
   Если посетитель выделил текст на странице, он подставится в форму сам.
3. Сообщение прилетит в Telegram («📩 Сообщение с сайта … Страница: …») и останется в списке 📩 Обратная связь.

Если на сайте настроен строгий Content-Security-Policy (например, `script-src 'self'; connect-src 'self'`), добавь адрес бота в `script-src` и `connect-src` — или положи `feedback-widget.js` к себе на сайт и разреши только `connect-src`.

**Публичная статус-страница**
В боте: ⚙️ Настройки → **🌐 Статус: включить** — и по адресу `https://твоё-имя.up.railway.app/status` появится страница «всё ли работает» с аптаймом, которую можно отправить кому угодно. Хочешь, чтобы адрес нельзя было угадать — добавь в Railway переменную `STATUS_PAGE_SLUG=любое-секретное-слово`, страница переедет на `/status/твоё-слово`.

**Google, Яндекс, Cloudflare** — подключаются прямо из бота: ⚙️ Настройки → **🩺 Диагностика и подключения** → кнопка у нужного пункта. Бот покажет два-три шага, примет токен или JSON-ключ сообщением, проверит его живым запросом и сохранит в своей базе. Переменные в `.env` для этого больше не нужны, но по-прежнему работают как запасной вариант (все они описаны в [.env.example](../.env.example)).

> **Чего на Railway не будет:** функций, которым нужен доступ к Docker на твоём собственном сервере — автоперезапуска *других* контейнеров и автоочистки диска (`AUTORESTART_CONTAINERS`, `AUTO_CLEANUP`). Они нужны только при самостоятельном хостинге на VPS и на Railway просто тихо отключаются, всё остальное работает полностью.

## Если что-то пошло не так

1. **Первым делом** — в боте: 📱 Меню → ⚙️ Настройки → **🩺 Диагностика и подключения**. Бот сам проверит свои части, а у каждого не-зелёного пункта будет кнопка с решением.
2. Посмотреть логи: в Railway открой сервис → **Deployments → View Logs**.
3. Перезапустить бота: меню ⋮ у сервиса → **Restart**.
4. Бот не отвечает на /start — проверь в **Variables**, что токен вставлен целиком и без пробелов, и что деплой в статусе **Active**.

## Как обновлять бота

**Код бота.** Когда выйдет новая версия:

1. Открой свой форк на GitHub — вверху появится плашка «This branch is N commits behind».
2. Нажми **Sync fork → Update branch**.
3. Railway увидит обновление и передеплоит бота сам.

Все твои сайты и настройки сохранятся — они живут в базе данных на подключённом диске, а не в коде.

**Библиотеки, из которых бот собран, обновляются сами.** В репозитории уже лежат три файла, которые это делают:

- `.github/dependabot.yml` — GitHub раз в неделю (по субботам) сам открывает pull request с обновлениями всех библиотек;
- `.github/workflows/ci.yml` — на этот PR автоматически запускаются проверки: линтер, ~70 тестов и `pip-audit` (поиск известных уязвимостей);
- `.github/workflows/dependabot-automerge.yml` — если проверки зелёные, PR вливается сам (кроме крупных версий: их лучше глянуть глазами).

Railway увидит новый коммит в `main`, передеплоит бота, а бот при старте напишет тебе: «🔄 Бот обновился: aiohttp 3.10.11 → 3.14.3». Раз в неделю он ещё и сам сверяет свои пакеты с базой уязвимостей и скажет, если что-то небезопасно.

Чтобы автомерж заработал, один раз в своём форке: **Settings → General → Pull Requests → ☑ Allow auto-merge**, и **Settings → Branches → Add rule** для `main` с включённым «Require status checks to pass» и выбранной проверкой «lint · test · audit». Без этого правила PR вливался бы, не дожидаясь тестов. GitHub Actions в публичном репозитории бесплатны.
