# TofsDevOps — полный список возможностей

Инвентарь всего, что умеет бот. Зачем это нужно и какую проблему решает каждая группа — в [WHY.md](WHY.md).

## 📡 Мониторинг

- **Доступность** каждые 5 минут — HTTP-статус, время ответа, редиректы.
- **Анти-флап** — инцидент открывается только после 2 последовательных фейлов; единичный чих сети не будит.
- **Вторая точка** — перед алертом «сайт лежит» перепроверка с внешних нод (check-host.net). Если извне сайт доступен — ложной тревоги не будет, придёт только пометка «похоже, сеть на моей стороне».
- **Медленные ответы** — 3 проверки подряд дольше 3 секунд → инцидент «performance», авторазрешение при восстановлении.
- **SSL** — ежедневная проверка с лестницей алертов (14 → 7 → 3 → 1 → 0 дней): одно уведомление на порог, а не ежедневный спам.
- **Контроль автопродления SSL** — бот следит за серийником сертификата: «автопродление, похоже, сломалось» приходит в алерт до того, как это стало пожаром. Продление, которое сработало само, — штатная работа: отдельного сообщения нет, дата попадает строкой в воскресный отчёт.
- **Домены** — проверка истечения по RDAP (IANA bootstrap → регистратура, rdap.org как редиректор; для .ru/.su/.рф — асинхронный WHOIS к TCI) с лестницей 30 → 14 → 7 → 3 → 1 → 0. Зоны без RDAP не создают шума: срок помечается как «не отслеживается».
- **DNS** — ежечасные снапшоты A/AAAA/CNAME (по хостам) и NS/MX (по домену). Изменение — алерт; смена NS-записей — критический (так выглядит угон домена).
- **Битые ссылки** — обход главной: любая неоткрывающаяся ссылка — 🟠, своя она или чужая, потому что посетитель упирается в тупик на вашей странице, а исправить её (новый адрес, копия из web.archive.org, убрать) можете только вы. Решает уверенность: 4xx, исчезнувший домен, плохой сертификат — сразу; таймаут, 5xx, отказ — только если ссылка не открывается и через три часа после первой неудачи (до тех пор «⚠️ перепроверю»): обход после перезапуска через пару минут не в счёт, иначе короткий сбой на той стороне — как у GitHub 09.11.2026 — становится «битой ссылкой». Если тревога снимается, пока ссылка ещё сбоит, бот так и говорит, а не «все ссылки работают». Трекеры, соцсети, preconnect и служебные пути Cloudflare пропускаются, «бот-блок» коды (401/403/429…) не считаются поломкой. Закрытый GitHub-репозиторий назван прямо: у посетителей там 404. Ручная проверка «🔗 Ссылки», которая не нашла ни битых, ни ждущих перепроверки, сразу закрывает проблему — не ждёт следующего обхода.
- **Глубокая проверка 5xx** — ежечасная выборка страниц из sitemap.xml: ловит «главная работает, а полсайта в ошибках».
- **Ключевая фраза / стоп-фраза** (на сайт) — страница должна содержать фразу («Корзина») или НЕ должна («Fatal error»). Регистр не важен, ищется в первом 1 МБ HTML. Ловит «HTTP 200, а на странице ошибка приложения»; вторая точка при этом не спрашивается — свой запрос уже прошёл, сеть ни при чём.
- **Свой HTTP-запрос** (на сайт) — метод GET/HEAD/POST/PUT/PATCH/DELETE/OPTIONS, заголовки построчно (`Authorization: Bearer …`), тело для POST-подобных методов; тело в JSON уходит с `Content-Type: application/json`, если свой заголовок не задан. API за токеном и POST-only health-эндпоинты мониторятся наравне с сайтами.
- **API-проверки — главная функция сайта**: `POST https://good-pass.pages.dev/api/v1/analyze` с телом `{"password":"…"}` и фразой `scoreLabel` в ответе, `GET https://fingerprint-api…workers.dev/api/whoami`. Правило одно (`utils/urls.py`, `is_api_check`): API — это http(s)-адрес, у которого метод не GET/HEAD, **или** путь `/api` и всё под `/api/`, **или** хост `api.…`. У API-проверки только ответ: код, фраза в ответе, время, порог фейлов и анти-флап. SEO-аудита, обхода ссылок, проверки 5xx по sitemap, подсказки фразы, проб ИИ-ботами, скриншота и замера из региона нет — GET на POST-эндпоинт дал бы 405 и ложную тревогу «сайт лежит». Сертификат, домен и DNS проверяются раз на адрес: если на том же хосте есть обычный сайт, у API их нет (одна тревога, не две), а карточка API ведёт на карточку сайта. Вторая точка (check-host шлёт голый GET) спрашивается только для GET/HEAD без своих заголовков — POST с телом снаружи не повторить. Адрес под `/api/` добавляется с путём и query как есть (путь чувствителен к регистру), обычная страница — как сайт целиком; на карточке строка «🔌 API-проверка: POST, в ответе должно быть «scoreLabel»», на статус-странице — метка API, путь без query. Сайт, переключённый на POST, сразу теряет старые находки поиска и ссылок.
- **Порог «медленно»** (на сайт) — с какого времени ответа считать сайт медленным (по умолчанию `SLOW_RESPONSE_MS`); три проверки подряд дольше порога → инцидент «performance».
- **TCP-порт и ICMP-ping** — `tcp://mail.example.com:25` и `ping://10.0.0.1` добавляются как обычные сайты: тот же анти-флап, вторая точка (check-host.net умеет tcp и ping; приватные адреса — 10.x, 192.168.x, .local — наружу не отправляются), инциденты, uptime и спарклайны. SSL/SEO/ссылки к ним, разумеется, не применяются.
- **Скорость из региона аудитории** — раз в час запрос с ноды check-host.net в стране твоего часового пояса (та же галочка, что вторая точка проверки): на карточке и в меню «быстро (0.8 с из России)» вместо замера из дата-центра бота. Лежащие сайты не замеряются.
- **Хост бота** — заполнение диска (порог настраивается) и статус docker-контейнеров.

## 🗣 Человеческий язык

- **Каждый алерт по одной схеме**: что случилось → что это значит для посетителей → что это обычно бывает → что делать (2–3 шага). Техническая строка («HTTP 502 · 0.81 с») последней, серым. Словарь из пятнадцати объяснений (`services/humanize.py`): ошибки сервера, таймаут, DNS, сертификат истекает/истёк/невалиден, домен, пропавшая фраза, стоп-фраза, медленно, битые ссылки, ошибки на страницах, noindex, смена DNS и NS, задача не отчиталась, диск, сервис на хосте.
- **Минуты вместо процентов**: «за неделю недоступен ≈3 мин», «открывается быстро (0.12 с)» — в сводках, отчётах и на экране «📈 Доступность».
- **Уровни — один словарь** (`services/humanize.py`), одинаковый в уведомлении, на экране «Проблемы», в меню, на карточке и в сводках: 🔴 — нужно действие сейчас (звонит, пробивает mute и тихие часы: сайт лежит, NS сменились, noindex или robots закрыли сайт, сертификат ≤3 дн., домен ≤7 дн., диск ≥95 %); 🟠 — нужно действие, но не сегодня (приходит тихо, ждёт тихие часы: сертификат ≤14 дн., домен ≤30 дн., битые ссылки — свои и чужие, 5xx в глубине, медленно, помехи в поиске и у ИИ, смена A/MX, задача не отчиталась); ✅ — снова работает; ⚠️ — не смог проверить; ℹ️ — факт, который не проблема (домен-IP). Факты штатной работы («проверил 3 страницы», «сертификат продлился сам») — подписью на экране и в сводках, без счётчика и без кнопки «что делать». Значок в тексте всегда совпадает с доставкой: 🔴 уходит как критичное, 🟠 — тихо.
- **Экран «Проблемы»**: заголовок и кнопка в меню берут худший из открытых уровней, у каждой строки свой значок, «ℹ️ Что делать» открывает, что это значит для посетителей, что обычно бывает и шаги (с кнопкой на экран, где это чинится), «🔧 Я чиню» и «✓ Закрыть».
- **Эскалация без капслока**: «лежит уже 1 ч 30 мин, продолжаю проверять каждую минуту» и кнопка «🔧 Я чиню» вместо повторного крика.
- **Правила игры при старте**: одно сообщение после `/start` и после первого сайта — как часто проверяю, когда пишу, когда молчу.

## 🔧 Самолечение

- **Кнопки-действия в алертах**: 🔍 перепроверить · 📸 скрин страницы · 🚀 передеплой (Cloudflare Pages Deploy Hook) · 🧹 сброс кэша Cloudflare. Починка — один тап из Telegram, без ноутбука и SSH.
- **Автопересборка** — при падении сайта бот сам дёргает deploy hook (включено по умолчанию, как только hook настроен; один раз на инцидент) и пишет в алерте «🤖 Уже сделал сам».
- **Автоперепроверка** — через 2 и 5 минут после алерта бот проверяет снова и дописывает вердикт в то же сообщение; если сайт поднялся, лишняя перепроверка снимается.
- **Ссылки в панели** — хостинг определяется по заголовкам ответа (Cloudflare, Vercel, Netlify, GitHub Pages, Railway, Render, Fly, Heroku, Timeweb, Beget), в алерте кнопка «🔗 Открыть панель …»; регистратор берётся из RDAP, алерт про домен ведёт в его панель.
- **Подсказка фразы** — при добавлении сайта бот предлагает следить за фразой с главной (h1 или title) одной кнопкой; заодно проверяет www-двойника.
- **Одна идея в неделю** — в конце воскресного отчёта одна рекомендация с кнопкой (фраза, статус-страница, Google, задачи и боты, Яндекс, Cloudflare), по кругу, никогда две. Фразу бот не просит придумать: читает её с главной сам и спрашивает «следить, чтобы была «…»?» — «✅ Да, следить» / «Не надо».
- **Автоперезапуск контейнеров** — упавший или unhealthy контейнер перезапускается (не чаще раза в 10 минут); «перезапустил — работает» или критический алерт, если не помогло.
- **Автоочистка диска** — при переполнении docker prune с отчётом «было 87% → стало 64%».

## 📲 Управление из чата

- **Онбординг** — для запуска нужен только токен бота: первый `/start` делает тебя админом (сохраняется в базе), пустое меню ведёт к добавлению первого сайта, добавленный сайт сразу проверяется («✅ работает, HTTP 200, SSL 77д»).
- **Сайты из меню** — «➕ Добавить» на главном экране (с валидацией) / кнопка сайта → карточка → ⚙️ → 🗑 убрать (мягко: история и инциденты сохраняются, мониторинг останавливается). Лимит 20 сайтов. `.env`-переменная `SITES` сидит базу только при первом запуске.
- **⚙️ Настройки** — час утренней сводки, вечерний отчёт вкл/выкл, час недельного отчёта, тихие часы пресетами; применяются к планировщику на лету, переживают рестарт.
- **⏰ Задачи и боты из меню** — «➕ Добавить» → «⏰ Бот или задача по расписанию» (имя + интервал: час/6 часов/сутки/неделя); каждая задача — строка и кнопка на главном экране рядом с сайтами, карточка с последней отметкой, готовой `curl`-строкой (для неё задай `PUBLIC_BASE_URL`) и удалением.
- **⏸ Пауза сайта** — «Пауза 1ч» / «До утра» из детальной проверки: проверки и инциденты продолжаются, алерты и эскалация молчат; в шапке меню виден счётчик пауз.
- **⚙️ Настройки на сайт** (кнопка сайта → ⚙️ → 🛠 Для продвинутых) — интервал проверки (1–60 мин, глобальный дефолт — 5), порог фейлов подряд до алерта (1–5), приемлемые HTTP-коды (`200-399,401` — страница за паролем перестаёт считаться поломкой), ключевая фраза с выбором режима. Новый интервал применяется сразу, без рестарта.
- **🔧 Тех. окна** (Настройки → 🔧) — регулярные окна тишины: каждый день / будни / выходные, время пресетами или своё, окна через полночь («23:00–06:00») работают корректно. На один сайт или на все; во время окна алерты и эскалация молчат, проверки и статистика продолжаются, в шапке меню — индикатор 🔧, на статус-странице — баннер.
- **🩺 Диагностика и настройка** — когда всё в порядке, одна строка «Бот работает, всё в порядке» и версия; иначе только то, что сломано (в том числе «новая версия не запустилась»), каждое со своей кнопкой. Необязательные подключения — за одной кнопкой «➕ Подключить ещё (N)». У каждой строки кнопка: одно действие (включить статус-страницу, новый heartbeat-секрет, вторая точка вкл/выкл) или мастер с шагами-кнопками. Интеграции вводятся из чата и хранятся в базе: токен Яндекса и токен GitHub проверяются живым запросом, ключ Google принимается файлом, deploy hooks и токен Cloudflare по одному. Строки, неприменимые на этой платформе, скрыты; публичный адрес на Railway определяется автоматически по `RAILWAY_PUBLIC_DOMAIN`.
- **👥 Помощники** (Настройки → 👥) — до трёх человек, которым тоже звонят тревоги 🔴 (сайт лёг и снова работает): отпуск или севший телефон владельца больше не значит, что о лежащем сайте никто не узнает. Приглашение — одноразовая ссылка на сутки; помощник получает только текст, без кнопок, управлять ботом не может, уходит сам командой /stop или его убирает владелец.
- **🔔 Пробная тревога** — через минуту после нажатия приходит образец тревоги «сайт лёг» (через минуту — потому что Telegram глушит телефон, пока ты в приложении); «🔕 Нет» объясняет, что поправить. Бот предлагает её сам после первого сайта.
- **✓ Закрытие инцидента** — любой инцидент можно закрыть по одному прямо из списка (не только «сбросить все»).
- **👀 «Видел, не напоминать 2 ч»** — на алерте эскалации и в списке инцидентов: повторные напоминания молчат, инцидент остаётся открытым, проверки идут.
- **📤 Экспорт / 📥 импорт** — JSON со всем, что настроено руками: сайты с настройками, часы сводок, тихие часы, часовой пояс, плановые работы, задачи и боты и введённые в чате подключения (в файле есть токены — хранить как пароль). Импорт добавляет и обновляет, лишнее не трогает, расписание перестраивает сразу. Тот же 📥 принимает `.db` из воскресного бэкапа и восстанавливает базу целиком (проверка, что это база бота; прежняя остаётся `.bak`).
- **🕐 Часовой пояс** (Настройки → 🕐) — города кнопками или свой ключ IANA; показывает текущее время; сводки, тихие часы и все времена в сообщениях пересчитываются сразу. `TIMEZONE` в `.env` — запасной вариант.
- **🔔 Будить: только «сайт лёг»** (Настройки → 🌅 Сводки и тихие часы) — остальное критичное (смена NS-серверов, сайт закрыт от поиска) ждёт конца тихих часов.
- **🌐 Статус-страница** (Настройки → 🌐) — включить/выключить и «🔑 Сделать ссылку секретной»: страница переезжает на `/status/<секрет>`, без него отвечает «не найдено».
- **📩 Обратная связь** («⚙️ Настройки») — всё, что прислали посетители через виджет, постранично, плюс готовый сниппет подключения с твоим секретом.

## 💓 Dead-man switch

- Джобы добавляются из чата («➕ Добавить» → «⏰ Бот или задача по расписанию») или через `HEARTBEAT_JOBS` в `.env`; endpoint `/api/heartbeat/<секрет>/<job>` — одна строка `curl` в конце крона бэкапа, а боту или сервису — тот же адрес как ссылка для отметок (в его настройках это обычно healthcheck URL). Слово «сторож» в боте значит только внешнего сторожа самого бота (healthchecks.io). На главном экране каждая задача видна рядом с сайтами: ✅ отметка вовремя, 🟠 молчит дольше интервала (+25%, как у алерта), ⏳ ждёт первой отметки, ⚠️ ни одной отметки после алерта. Карточка задачи начинается не со строки `curl`, а с вопроса «Что такое X у тебя?»: «🤖 Это бот или сервис» (адрес, который нажатием копируется, и где у бота такое поле), «🗓 Это задача по расписанию» (готовые строки для GitHub Actions, cron и планировщика хостинга) или «🗑 Такой задачи нет — убрать». Убрать можно и задачу из `HEARTBEAT_JOBS` на сервере: бот перестаёт её ждать, искать переменную не нужно.
- Вотчер: молчание дольше заявленного интервала (+25% слака) → алерт «💔 backup молчит»; возобновление → «💚 снова подаёт сигналы».
- **Что видит другой бот — на том же экране.** Бот, который следит не только за собой (SocialTracker — за каналами и подписчиками), присылает вместе с отметкой строку на каждую вещь: «✅ Telegram-канал · 12 340, +18 за сутки», «🟠 LinkedIn · cookie истекает через 3 дн.». Они стоят отдельным блоком на главном экране, в «Проверить всё сейчас», в карточке задачи (с кнопкой «↗️ Открыть» его) и в утренней сводке; замечание портит заголовок, как у сайта. Замолчал бот — вместо старых строк «⚠️ молчит — не знаю, что сейчас». Свои тревоги и подробные экраны остаются у него. Формат — в [DEVELOPMENT.md](DEVELOPMENT.md#статус-от-другого-бота).
- В утренней сводке боты и задачи стоят сразу под сайтами, строка на каждую, как у сайта: «✅ socialtracker — работает, отметка 1 дн назад (жду раз в сутки)» — ожидаемый ритм рядом объясняет, почему «1 дн назад» в порядке. Молчащая или ни разу не отметившаяся задача — 🟠/⚠️, убирает «Всё спокойно» и приносит под сводкой кнопки «🔗 Подключить» и «🗑 Удалить».

## 🔍 SEO / GEO (видимость для поисковиков и AI)

- **Экран «🔎 Поиск и ИИ»** — открывается мгновенно из снимка ежедневного аудита и говорит ровно то, что измерено: «сайт открыт для поисковиков и ИИ-ассистентов, помех нет» / «открыт, но есть N помех» / «🔴 закрыт от поиска». Есть ли сайт в индексе на самом деле, знают только Google и Яндекс: без Search Console и Вебмастера экран так и пишет и предлагает их подключить; с ними — строки «📇 Google: главная в индексе (обход 20.09)» и «📇 Яндекс: 12 стр. в поиске, ИКС 10» из ежедневной проверки индекса, а данные старше двух дней помечаются «по данным на DD.MM». Ниже пронумерованный список помех — каждая с уровнем, заголовком по-человечески, «чем грозит» и кнопкой «💡 Что делать» с шагами под определённый по заголовкам хостинг (Cloudflare, Vercel, Netlify, GitHub Pages или свой сервер) и ссылками: robots.txt, sitemap, тестовый несуществующий адрес, проверка Google, панель хостинга. Списка «мелочей» нет: каждая строка — действие, а «проверил 3 страницы, без JavaScript видно 4 000 символов» — подпись внизу. «🔄 Проверить снова» — живой аудит за 30 секунд, он же обновляет данные Google и Яндекса. Критичный алерт несёт те же кнопки.
- **Ежедневный аудит** (07:30); сайт, добавленный сегодня, первый раз аудируется тихо.
- **Детектор noindex** — meta robots и заголовок `X-Robots-Tag` на выборке страниц; критический алерт, пробивающий любые заглушки.
- **robots.txt** — запрет Googlebot/YandexBot критичен; запрет GPTBot/ClaudeBot/PerplexityBot — предупреждение.
- **Пробы AI-юзерагентами** — бот запрашивает страницы как GPTBot/ClaudeBot/PerplexityBot и ловит 403 (случайно включённая блокировка AI-ботов в Cloudflare).
- **Замер контента без JavaScript** — сколько текста реально видят AI-краулеры (они не исполняют JS).
- Проверки title и description (есть ли и не слишком ли короткие/длинные), canonical (ведёт ли на https и на этот же сайт), h1, OpenGraph-превью, lang, JSON-LD — каждая находка 🟠 с шагами. Того, что не требует действия (нет robots.txt — всё разрешено; закрыт порт 80; есть или нет `llms.txt`; нет canonical у страницы с одним адресом), в списке нет.
- Детект soft-404 (несуществующие страницы должны отдавать 404) и редиректа http→https.
- **Google Search Console** (опционально) — «главная в индексе?» ежедневно через URL Inspection; клики и показы неделя-к-неделе в воскресном отчёте. Авторизация сервис-аккаунтом, без google-SDK.
- **Яндекс.Вебмастер** (опционально) — страницы в поиске, ИКС, новые FATAL/CRITICAL проблемы сайта.

## 📊 Отчёты и уведомления

- **Утренняя сводка** — одно сообщение: строка на сайт, открытые проблемы со своим значком у каждой (без отступов — Telegram всё равно переносит строку к левому краю; поисковая находка начинается с сути: «нет карты сайта и ещё 1 помеха»), простой за 7 дней одной фразой («все сайты без сбоев») или списком только упавших, ближайшие истечения SSL/доменов, диск; под сайтами — строка на каждого бота и задачу и строка внешнего сторожа («✅ Сторож healthchecks.io — на связи: если я упаду, он сообщит»). «🔎 Поиск и ИИ» не повторяет то, что уже в открытых проблемах: «помех нет» или только сайты, которые не удалось проверить. Читается за 10 секунд.
- **Вечерний отчёт** — приходит только если есть активные инциденты.
- **Недельный отчёт** (воскресенье) — простой за 7/30/90 дней (сырые проверки + ночные агрегаты, так что 90 дней честные даже при `RETENTION_DAYS=30`), ASCII-график среднего времени ответа по дням в `<pre>` (никакого matplotlib), «Открыто сейчас» — все открытые проблемы со своим уровнем, сколько бы им ни было, и «Решено за неделю» с ✓, сертификаты, продлившиеся сами, поисковые метрики Google/Яндекса, состояние зависимостей бота, порядок в GitHub. Это то место, где обещано показывать всё 🟠. Длинный отчёт делится на несколько сообщений, а не обрезается.
- **Порядок в GitHub** (опционально: `GITHUB_TOKEN` или «🩺 Диагностика → 🐙 GitHub») — раздел воскресного отчёта. Один GraphQL-запрос по репозиториям владельца (`GITHUB_OWNER`, по умолчанию — аккаунт токена), и только то, что просит руки: репозитории, пропавшие с прошлой недели (список хранится в базе), PR старше 7 дней, лишние ветки (не основная и не голова открытого PR; `gh-pages` не в счёт), выключенное «Automatically delete head branches», красный CI на последнем коммите основной ветки, открытые алерты Dependabot — если токену можно их читать, иначе строки просто нет. Архивы и форки смотрятся только на исчезновение. Всё в порядке — раздела нет; GitHub не ответил или не принял токен — одна строка «⚠️ GitHub: не смог проверить», отчёт приходит как обычно. Dependabot-PR самого бота здесь не повторяются — они уже в строке зависимостей.
- **Тихие часы** — некритичные уведомления ночью копятся и приходят утром одним дайджестом; «сайт лежит» проходит всегда.
- **Эскалация** — лежащий сайт напоминает о себе каждые 30 минут, игнорируя mute (сознательно только доступность: force-пейджинг каждые полчаса об истекающем SSL приучил бы игнорировать алерты).
- **Итоги инцидентов** — «✅ Восстановлен · лежал 12 мин (14:03–14:15) · причина: HTTP 502» вместо двух сообщений, которые надо склеивать в голове.
- **Mute** — `/mute 8h` или пресеты в меню; критические алерты пробивают тишину, остальное не теряется — копится и приходит дайджестом после снятия.
- **Тихая доставка** — 🟠 и восстановления приходят без звука (`disable_notification`); звонят только 🔴 (переключатель «Будить: только «сайт лёг»» оставляет звонок одной доступности).
- **Единый принцип**: алерты только при смене состояния — ничего не повторяется, пока ситуация не изменилась.

## 📱 UX в Telegram

- **Всё под присмотром — на одном экране** — главный экран сам показывает «✅ 4/4 в порядке · проверял 2 мин назад», строку на каждый сайт («✅ s.morgunov.tech · быстро», «🟠 … · сертификат через 10 дн., 2 помехи в поиске», «🔴 … · закрыт от поиска») и блок «⏰ Задачи и боты» («✅ socialbot · отметка 3 ч назад»), проблемы прямо в тексте со своим значком. У каждой строки своя кнопка — один тап до карточки сайта или задачи (до пяти — по одной в ряд, больше — по две). Ниже «🔎 Проверить всё сейчас» (в конце отчёта — отметки задач), «➕ Добавить» (сайт; API, порт или ping; бот или задача по расписанию) и «⚙️ Настройки»; «Проблемы (N)» со значком худшего уровня — первой кнопкой и только пока что-то открыто. Карточка сайта — всё о сайте на одном экране. В «⚙️ Настройках» — только то, что не про «всё ли в порядке»: сводки и тихие часы, тишина на время, плановые работы, часовой пояс, диагностика и подключения (там же тест алерта), статус-страница, обратная связь, экспорт/импорт. Старые кнопки «🌍 Сайты» и «⏰ Контроль задач» в прежних сообщениях ведут на главный экран.

## 🌐 Публичная статус-страница

- **Одна кнопка** (Настройки → 🌐) — и по адресу `/status` появляется страница в духе Uptime Kuma: баннер «всё работает / часть систем недоступна / технические работы», по каждому сайту текущий статус и uptime за 24ч/7д/30д/90д, история инцидентов за 14 дней. Рядом `/status.json` с теми же данными для своих дашбордов.
- **Приватность продумана**: выключена по умолчанию (список сайтов — тоже информация); история инцидентов обезличена — тип и длительность, без внутренних текстов ошибок; `noindex` в мета и заголовках; необязательный секретный slug (`STATUS_PAGE_SLUG`) прячет страницу на `/status/<slug>`.
- **SVG-бейджи аптайма** shields-стиля — `/status/badge/<id>.svg` для README или внутренней вики.
- Страница рендерится из базы (никаких живых проверок по заходу — ей нельзя заставить бота долбить ваши сайты), кэш 30 секунд, тёмная тема по prefers-color-scheme, автообновление раз в минуту.

## 📩 Виджет обратной связи

- Встраиваемый JS-виджет для сайтов: плавающая кнопка «⚠️ Проблема?» или `button: false` + атрибут `data-devops-feedback` на любой ссылке («нашли опечатку?» в футере). Выделенный на странице текст подставляется в форму. Сообщение прилетает в Telegram с ID и IP и остаётся в боте («📩 Обратная связь»).
- Сервер: CORS/preflight, rate limiting (5/мин на IP, 30/мин глобально; за прокси берётся последний адрес из `X-Forwarded-For`), жёсткие лимиты размеров. Секрет виджета публичный по природе, поэтому у heartbeat свой.

## 🧹 Самообслуживание

- **Ретенция** — сырые результаты проверок старше 30 дней ночью сворачиваются в дневные агрегаты: база не растёт бесконечно.
- **Бэкапы своей БД** — ночной `VACUUM INTO` с ротацией + раз в неделю копия отправляется документом в Telegram (офф-хост копия без всякой инфраструктуры).
- **Self-heartbeat** — пинг внешнего сторожа (healthchecks.io) каждые 5 минут: если умрёт сам бот, вы узнаете от сторожа. Ссылка вводится из чата (Диагностика → 🛡 Подключить сторожа), бот проверяет её живым пингом; `SELF_HEARTBEAT_URL` в `.env` — запасной вариант. Бот читает ответ сторожа, а не только код: на удалённый или недокопированный check healthchecks.io отвечает HTTP 200 «OK (not found)», и такая ссылка больше не считается подключённой. Состояние сторожа — на главном экране (в блоке «⏰ Задачи и боты») и в утренней сводке: ✅ пока он принимает отметки, 🟠 после четверти часа отказов; полчаса отказов — одно сообщение «сторож не принимает отметки», и одно — когда снова принимает.
- **Тишина не врёт** — бот молчит, когда всё хорошо, поэтому следит, чтобы молчание не значило ничего другого. Сообщение, которое Telegram не принял (нет сети, 5xx, лимит), не теряется: оно ждёт в очереди и уходит, как только Telegram ответит, с пометкой «⏳ Не дошло в 14:03». Если бота не было дольше 10 минут, после запуска он говорит, когда его не было и что сейчас с сайтами, а утреннюю сводку, пропущенную за это время, присылает с опозданием. После первого сайта бот предлагает пробную тревогу (через минуту, чтобы Telegram не глушил телефон, пока ты в приложении) — с подсказкой, что поправить, если не зазвонило, — и подключить внешнего сторожа.
- **База на постоянном диске** — на Railway без подключённого диска база стирается при каждом обновлении, и бот раз в неделю забывал бы сайты и хозяина. Бот проверяет, что файл базы лежит на диске Railway, и если нет — говорит сразу после /start, при каждом запуске и в 🩺 Диагностике, с готовыми шагами.
- **Контроль зависимостей** — обновления приезжают сами: Dependabot + CI (включая сборку Docker-образа) + автомерж, и после редеплоя бот пишет «🔄 Бот обновился: …». Робот автомержа сам дожидается тестов и вливает только зелёное — правило ветки в форке для этого не нужно. Поэтому «есть новая версия на PyPI» — не новость и не строка в отчёте. Бот говорит только о том, что без человека не встанет: уязвимые пакеты (OSV, один раз), мажорные PR («ждут твоего решения») и минорные, что висят дольше двух дней (тесты упали). Раз в час бот сверяет свою сборку с последним коммитом в main: если хостинг не смог его задеплоить, один раз пишет «🟠 Новая версия бота не запустилась» с кнопкой на лог сборки — иначе бот молча жил бы на старой версии, а все следующие обновления падали бы так же.
- **Секреты** — пустые или шаблонные `WEBHOOK_SECRET`/`HEARTBEAT_SECRET` заменяются сгенерированными (хранятся в базе, видны в 🩺 Диагностике). Heartbeat принимается только с heartbeat-секретом: webhook-секрет виден в коде виджета на сайте, и с ним любой посетитель мог бы «оживить» молчащую задачу.
- Инженерное: единое SQLite-соединение (WAL, write-lock, upserts без гонок, миграции схемы через `PRAGMA user_version`), 19 задач планировщика (доступность тикает раз в минуту и сама решает, кому пора по его личному интервалу), все сообщения идут через один `notifier` с тремя приоритетами, все интеграции опциональны и молча отключаются без ключей, все времена — в вашей таймзоне (`zoneinfo`), ~150 тестов и CI.
