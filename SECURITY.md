# Security

Please report vulnerabilities privately: on GitHub open **Security → Report a vulnerability** in this repository. Don't open a public issue for them. Fixes land on `main`, which the Railway template and the `:latest` image follow; there are no maintained older branches.

## What the bot holds and how it treats it

- **The bot token** lives only in the environment (`TELEGRAM_BOT_TOKEN`). Integration keys you connect from the chat (Google Search Console, Yandex.Webmaster, Cloudflare, the CrUX key, a GitHub token) are stored in the SQLite database on your volume; the environment wins over the database when both are set. «🔌 Подключения» shows whether a key is set, never its value.
- **Logs never carry secrets.** One `RedactingFormatter` (`utils/redact.py`) covers every logger: the Bot API token, keys in query strings, passwords in URLs and the values the bot knows are secret are replaced before a line is written; the chatty HTTP loggers stay at WARNING.
- **The database** holds your sites, their check history, incidents, settings and the keys above. The nightly copies in `data/backups/` are complete and stay on the server with mode 0600 — keep the volume like a password store. The Sunday copy the bot sends to the owner's private chat (never to a group) is made without connection tokens, secrets, API-check headers and bodies and visitors' IPs; «🔔 Когда писать» switches it off.
- **Who may talk to the bot.** The owner is `TELEGRAM_ADMIN_USER_ID` when set, otherwise the first `/start` in a private chat; everyone else is refused, with a rate limit on refusals. Helpers (people you add) receive 🔴 alerts only. In a group the bot shows no keyboard and answers no stranger.
- **What visitors can reach.** The public status page, its badges and the feedback widget are served on `WEBHOOK_PORT` (8080, plain HTTP — put a proxy in front and set `TRUST_PROXY`). The widget secret is public by design (it sits in the page code); the heartbeat secret is always a different one, and «🔑» in «🔌 Подключения» rotates every job address at once. Widget messages reach you with the visitor's IP; nothing else about visitors is stored.
- **`docker.sock` is root on the host.** Mount it only where everything is yours; the bot then restarts the containers in `AUTORESTART_CONTAINERS` and, only with `AUTO_CLEANUP=1`, removes dangling images and old build cache. A filtered socket is described in `docs/SETUP.md`.
- **What leaves your server** is listed line by line in the README (section «What leaves your server»), with a switch for each line. Internal addresses (10.x, 192.168.x, `.local`, `.lan`, …) never go to any outside service.
- **Supply chain.** `requirements.txt` is a hashed lock compiled from `requirements.in`; the image and CI install it with `--require-hashes --no-deps`. CI runs `pip-audit --strict` on the lock and on the dev tools, builds the image and runs it (`id -u` = 10001, the data directory writable); Actions are pinned by commit SHA and the base image by digest. Dependabot's weekly PR merges itself only for patch and minor updates of the Python libraries after a green CI; the base image, the Actions and major versions wait for a human. The container drops root in `entrypoint.sh` after handing the data directory to the bot's user. Every Sunday the bot checks its own packages against OSV and tells you about known vulnerabilities.
