# TofsDevOps — сам себе DevOps в Telegram

> Мониторит сайты, чинит что может, проверяет, что тебя видят поисковики **и ИИ-ассистенты** — и молчит, пока всё в порядке.

🇬🇧 [Read in English](README.md) · [Зачем это вам](docs/WHY.md) · [Полный список возможностей](docs/FEATURES.md) · [Установка по кликам](docs/SETUP.md)

Для людей, которые не знают, что такое DNS и ошибка 502. Три кнопки: **всё ли везде ок**, **один сайт подробно**, **настройки**. Каждый алерт говорит, что случилось, что это значит для посетителей и что делать — кнопкой на каждый шаг, под твой хостинг (Cloudflare, Vercel, Netlify, GitHub Pages или свой сервер).

## Что получаешь

- **Доступность, SSL, домен, DNS, битые ссылки, ошибки в глубине сайта** — один конвейер инцидентов: анти-флап, вторая точка проверки снаружи перед тем, как будить, лестница алертов вместо ежедневного нытья, простой в минутах, а не в процентах.
- **API-проверки** — следит за тем, что сайт делает (`POST /api/v1/analyze` должен ответить `scoreLabel`): у адреса под `/api/` или запроса не GET — только код, фраза и время ответа, без шума SEO и ссылок и без второй тревоги о сертификате рядом с сайтом.
- **Видимость в поиске и у ИИ** — noindex, robots.txt, блокировка ИИ-ботов, пустая страница без JavaScript, soft-404, карта сайта. Каждая находка — пронумерованный пункт с «чем грозит» и шагами под твой хостинг.
- **Самолечение** — пересборка и сброс кэша Cloudflare Pages, перезапуск контейнеров и очистка диска на своём сервере, с отчётом, что уже сделано.
- **Отчёты, уважающие внимание** — одна строка утром, воскресная сводка с ASCII-графиками (а с read-only токеном GitHub — что прибрать в репозиториях: старые PR, лишние ветки, красный CI, пропавшие репозитории), тихие часы, режим «я чиню», свой часовой пояс, полный экспорт/импорт и восстановление базы из чата. Один словарь уровней везде: 🔴 — чинить сейчас (звонит), 🟠 — не сегодня (тихо), а то, что в порядке, — подпись, а не сообщение.

## Быстрый старт — 5 минут, без сервера

[![Deploy on Railway](https://railway.com/button.svg)](https://railway.com/deploy/lVRuwW)

1. Создай бота у [@BotFather](https://t.me/BotFather) и скопируй токен.
2. Нажми **Deploy on Railway** выше и вставь токен — это единственное поле. Диск для базы, адрес в интернете и остальное уже в шаблоне.
3. Отправь боту `/start` — первый пользователь становится админом и добавляет первый сайт прямо в чате. Потом бот предложит пробную тревогу и внешнего сторожа, а остальное подскажет его чек-лист («⚙️ Настройки → Диагностика»).

Хочешь свою копию кода? Форкни репозиторий → Railway → **Deploy from GitHub repo** → переменная `TELEGRAM_BOT_TOKEN`, диск на `/app/data`, сгенерированный домен на порту 8080.

Подробно по кликам — [docs/SETUP.md](docs/SETUP.md). Свой сервер (Docker Compose), все интеграции из `.env`, архитектура и разработка — [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md).
