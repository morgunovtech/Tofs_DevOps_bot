# TofsDevOps — сам себе DevOps в Telegram

> Мониторит сайты, чинит что может, проверяет, что тебя видят поисковики **и AI-агенты** — и молчит, пока всё в порядке.

🇬🇧 [Read in English](README.md) · [Зачем это вам](docs/WHY.md) · [Полный список возможностей](docs/FEATURES.md)

Собран вокруг одного принципа: **минимальное вовлечение**. Ты не должен нянчить инфраструктуру — бот сам скажет, когда нужно внимание, сначала попробует починить сам, а что всё хорошо — докажет одной короткой сводкой в день.

## Что умеет

### 📡 Мониторинг
- **Доступность** каждые 5 минут — с нюансом: перед тем как разбудить тебя, перепроверяет сайт с внешних нод (check-host.net). Если для остального мира сайт жив — ложной тревоги не будет.
- **SSL-сертификаты** — лестница алертов (14 → 7 → 3 → 1 → 0 дней) вместо ежедневного нытья, плюс *контроль продления*: бот следит за серийником сертификата и предупредит, когда автопродление (Cloudflare/certbot) молча сломалось.
- **Истечение домена** по WHOIS со своей лестницей алертов.
- **Изменения DNS** — ежечасные снапшоты A/AAAA/CNAME/NS/MX; смена NS-записей (так выглядит угон домена) — критический алерт.
- **Битые ссылки** — обходит страницы и отделяет *твои* битые ссылки (надо чинить) от недоступных внешних (шум).
- **Глубокая проверка 5xx** — ежечасная выборка страниц из `sitemap.xml`: ловит «главная работает, а полсайта в ошибках».
- **Здоровье хоста** — диск и docker-контейнеры на сервере, где живёт бот.

### 🔍 SEO / GEO (видимость для AI)
- **Детектор noindex** — классическая тихая авария: один кривой деплой уносит `<meta name="robots" content="noindex">` в прод, а узнаёшь через месяц по графику трафика. Бот узнаёт в тот же день и пробивает любые заглушки.
- **robots.txt** — запрет Googlebot/YandexBot критичен; запрет GPTBot/ClaudeBot/PerplexityBot — предупреждение (ты *хочешь*, чтобы AI-агенты тебя видели).
- **Пробы AI-юзерагентами** — запрашивает страницы как GPTBot/ClaudeBot/PerplexityBot и алертит на 403 (привет, случайно включённая галочка «Block AI bots» в Cloudflare).
- **Замер контента без JS** — AI-краулеры не исполняют JavaScript. Если твоя страница — SPA с 60 символами текста до выполнения JS, AI-агенты видят пустоту — бот об этом скажет.
- Проверки title/description/canonical/h1/OpenGraph/JSON-LD, детект soft-404, наличие `llms.txt`.
- **Реальный статус индексации** (опционально): Google Search Console API (главная выпала из индекса → критический алерт; клики/показы в еженедельном отчёте) и API Яндекс.Вебмастера (страницы в поиске, ИКС, проблемы сайта).

### 🔧 Самолечение (дружит с Cloudflare Pages)
- К алертам прикреплены **кнопки-действия**: перепроверить, дёрнуть Deploy Hook (пересборка Pages), сбросить кэш Cloudflare, снять живой скриншот страницы.
- **Автопередеплой**: опционально сам дёргает deploy hook при падении сайта (раз на инцидент) и отчитывается, что сделал.
- **Автоперезапуск контейнеров** и **автоочистка диска** (docker prune) на хосте бота — выключено по умолчанию, включается монтированием docker socket.

### 📱 Полное управление из чата
- **Онбординг без конфигов** — первый, кто нажмёт `/start`, становится админом; пустой бот сам ведёт к добавлению первого сайта и сразу его проверяет.
- **Сайты** — добавление/удаление из меню («🌍 Сайт детально») с мгновенной первой проверкой. Источник истины — база; `.env` лишь необязательный сид при первом запуске.
- **⚙️ Настройки** — час утреннего отчёта, вечерний вкл/выкл, тихие часы: меняются из чата и применяются к работающему планировщику на лету.
- **💓 Heartbeat-джобы** — добавляются из чата, бот выдаёт готовую строку `curl` для крона.
- **⏸ Пауза сайта** — деплоишь большое? Поставь алерты на паузу на час или до утра; проверки продолжаются молча.
- **🩺 Диагностика** — самопроверка в один тап: база, веб-сервер, docker socket, токены Google/Яндекса (живыми запросами), сервис скриншотов.
- **🔔 Тест алерта** — увидь, как выглядит критическое уведомление, до того как оно понадобится.

### 💓 Dead-man switch
Крон бэкапа не может сообщить, что он *не* отработал. Добавь джобу в чате («📋 Ещё» → «💓 Heartbeats») — бот выдаст готовую строку для крона:

```bash
curl -fsS https://your-server:8080/api/heartbeat/<секрет>/backup
```

…и бот сам заметит, что джоба молчит дольше положенного. Восстановление объявляется автоматически.

### 📊 Отчёты, уважающие твоё внимание
- **Утренняя сводка** — одно сообщение: статус сайтов, uptime за 7 дней, ближайшие истечения SSL/доменов, статус heartbeat-джоб, диск, SEO. Читается за 10 секунд.
- **Еженедельный отчёт** (воскресенье) — uptime, инциденты, график времени ответа, метрики Google/Яндекса неделя-к-неделе.
- **Тихие часы** — некритичное ночью копится и приходит утром одним дайджестом. «Сайт лежит» пробивается всегда.
- **Тихая доставка** — информационные сообщения приходят без звука; звонят только критические алерты. Тишина по умолчанию — буквально.
- **Эскалация** — лежащий сайт напоминает о себе каждые 30 минут и игнорирует mute. Мёртвый сайт нельзя забыть (сознательно только доступность — пейджинг каждые полчаса об истекающем сертификате приучил бы игнорировать алерты).
- **Итоги инцидентов** — сообщение о восстановлении содержит длительность и причину: *«✅ Восстановлен · лежал 12 мин (14:03–14:15) · причина: HTTP 502»*.

### 🧹 Обслуживает сам себя
- Старые сырые проверки ночью сворачиваются в дневные агрегаты — SQLite не растёт бесконечно.
- Ночные бэкапы базы с ротацией + еженедельная офф-хост копия прямо в твой Telegram-чат.
- Собственный heartbeat на внешний сторож (healthchecks.io) — кто сторожит сторожа.

### 📩 Бонус: виджет обратной связи
Встраиваемый JS-виджет («Сообщить о проблеме») для твоих сайтов — сообщения прилетают в Telegram, на сервере rate limiting и лимиты размера.

## Быстрый старт

Нужны: Docker и токен бота от [@BotFather](https://t.me/BotFather).
Не дружишь с терминалом — есть [пошаговая инструкция простым языком](docs/SETUP.md).

```bash
git clone https://github.com/morgunovtech/devops-bot.git
cd devops-bot
cp .env.example .env
# Заполни ОДНО значение: TELEGRAM_BOT_TOKEN (от @BotFather)
docker compose up -d --build
```

Отправь боту `/start` — первый пользователь становится админом, и бот сам
проведёт через добавление первого сайта. Сайты, время отчётов, тихие часы и
heartbeat-джобы управляются из чата; `.env` нужен только для опциональных
интеграций ниже (задокументированы в [.env.example](.env.example)):

| Что включается | Переменные |
|---|---|
| Кнопка передеплоя + автопередеплой | `DEPLOY_HOOKS`, `AUTO_REDEPLOY` |
| Кнопка сброса кэша Cloudflare | `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ZONE_ID` |
| Dead-man switch | `HEARTBEAT_JOBS` |
| Статус индексации Google | `GSC_SERVICE_ACCOUNT_FILE`, `GSC_PROPERTY` |
| Статус индексации Яндекса | `YANDEX_WEBMASTER_TOKEN` |
| Перезапуск контейнеров / очистка диска | `AUTORESTART_CONTAINERS` + монтирование docker.sock |
| Внешний сторож | `SELF_HEARTBEAT_URL` |

## Архитектура

```
main.py                 точка входа: БД → веб-сервер → планировщик → polling
├── monitors/           доступность, ssl, домены, dns, ссылки, 5xx,
│                       seo/geo, хост — каждый пишет проверки и ведёт инциденты
├── services/           действия Cloudflare, Docker API, скриншоты,
│                       Google Search Console, Яндекс.Вебмастер
├── reports/            планировщик (19 джоб), форматтеры, недельный график
├── handlers/           меню-дашборд в Telegram и кнопки алертов
├── web/                aiohttp: API фидбека, heartbeat, виджет
└── db/                 aiosqlite, WAL, ретенция, бэкапы
```

Стек: Python 3.12, [aiogram 3](https://github.com/aiogram/aiogram), aiohttp, APScheduler, SQLite (WAL), matplotlib. Внешних систем мониторинга нет — бот и *есть* мониторинг.

Про модель безопасности виджета: «секрет» виджета уезжает каждому посетителю сайта, поэтому endpoint считается публичным — защита строится на rate limiting и жёстких лимитах размера, а не на токене. Осознанный и задокументированный компромисс для инструмента личного масштаба.

## Статус

Личный проект: собран для моих сайтов и выложен как есть — без SLA и обещаний по роадмапу. Issues и PR приветствуются — особенно новые мониторы и более умное самолечение.
