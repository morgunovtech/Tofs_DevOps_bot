# TofsDevOps — сам себе DevOps в Telegram

> Мониторит сайты, чинит что может, проверяет, что тебя видят поисковики **и AI-агенты** — и молчит, пока всё в порядке.

🇬🇧 [Read in English](README.md) · [Зачем это вам](docs/WHY.md) · [Полный список возможностей](docs/FEATURES.md)

Собран вокруг одного принципа: **минимальное вовлечение**. Ты не должен нянчить инфраструктуру — бот сам скажет, когда нужно внимание, сначала попробует починить сам, а что всё хорошо — докажет одной короткой сводкой в день.

## Что умеет

### 📡 Мониторинг
- **Доступность** каждые 5 минут — с нюансом: перед тем как разбудить тебя, перепроверяет сайт с внешних нод (check-host.net). Если для остального мира сайт жив — ложной тревоги не будет.
- **SSL-сертификаты** — лестница алертов (14 → 7 → 3 → 1 → 0 дней) вместо ежедневного нытья, плюс *контроль продления*: бот следит за серийником сертификата и предупредит, когда автопродление (Cloudflare/certbot) молча сломалось.
- **Истечение домена** по RDAP (протокол, заменивший WHOIS для gTLD в 2025 году; IANA bootstrap + rdap.org, для .ru/.su/.рф — маленький асинхронный WHOIS-запасной вариант) со своей лестницей алертов.
- **Изменения DNS** — ежечасные снапшоты A/AAAA/CNAME/NS/MX; смена NS-записей (так выглядит угон домена) — критический алерт.
- **Битые ссылки** — обходит страницы и отделяет *твои* битые ссылки (надо чинить) от недоступных внешних (шум).
- **Глубокая проверка 5xx** — ежечасная выборка страниц из `sitemap.xml`: ловит «главная работает, а полсайта в ошибках».
- **Ключевая фраза / стоп-фраза** — на сайт: алерт, когда фраза пропала со страницы или когда появилась плохая («Fatal error»). Ловит классическое «HTTP 200, а на странице белый экран».
- **Свой HTTP-запрос** — на сайт: метод (GET/HEAD/POST…), заголовки (`Authorization: Bearer …`) и тело запроса, так что API за токеном или POST-only health-эндпоинт мониторятся как обычные сайты.
- **TCP- и ping-мониторы** — `tcp://mail.example.com:25`, `ping://10.0.0.1`: не-HTTP сервисы (почта, SSH, БД) получают тот же конвейер инцидентов, анти-флап и вторую точку проверки.
- **Здоровье хоста** — диск и docker-контейнеры на сервере, где живёт бот.

### 🔍 SEO / GEO (видимость для AI)
- **Детектор noindex** — классическая тихая авария: один кривой деплой уносит `<meta name="robots" content="noindex">` в прод, а узнаёшь через месяц по графику трафика. Бот узнаёт в тот же день и пробивает любые заглушки.
- **robots.txt** — запрет Googlebot/YandexBot критичен; запрет GPTBot/ClaudeBot/PerplexityBot — предупреждение (ты *хочешь*, чтобы AI-агенты тебя видели).
- **Пробы AI-юзерагентами** — запрашивает страницы как GPTBot/ClaudeBot/PerplexityBot и алертит на 403 (привет, случайно включённая галочка «Block AI bots» в Cloudflare).
- **Замер контента без JS** — AI-краулеры не исполняют JavaScript. Если твоя страница — SPA с 60 символами текста до выполнения JS, AI-агенты видят пустоту — бот об этом скажет.
- Проверки title/description/canonical/h1/OpenGraph/JSON-LD, детект soft-404, наличие `llms.txt`.
- **Реальный статус индексации** (опционально): Google Search Console API (главная выпала из индекса → критический алерт; клики/показы в еженедельном отчёте) и API Яндекс.Вебмастера (страницы в поиске, ИКС, проблемы сайта).

### 🔧 Самолечение (дружит с Cloudflare Pages)
- К алертам прикреплены **кнопки-действия**: перепроверить, дёрнуть Deploy Hook (пересборка Pages), сбросить кэш Cloudflare, снять живой скриншот страницы.
- **Автопередеплой**: опционально сам дёргает deploy hook при падении сайта (раз на инцидент) и отчитывается, что сделал.
- **Автоперезапуск контейнеров** и **автоочистка диска** (docker prune) на хосте бота — выключено по умолчанию, включается монтированием docker socket.

### 📱 Полное управление из чата
- **Онбординг без конфигов** — первый, кто нажмёт `/start`, становится админом; пустой бот сам ведёт к добавлению первого сайта и сразу его проверяет.
- **Сайты** — добавление/удаление из меню («🌍 Сайт детально») с мгновенной первой проверкой. Источник истины — база; `.env` лишь необязательный сид при первом запуске.
- **⚙️ Настройки** — час утреннего отчёта, вечерний вкл/выкл, час недельного отчёта, тихие часы: меняются из чата и применяются к работающему планировщику на лету.
- **⚙️ Настройки на сайт** — интервал проверки, порог фейлов подряд, приемлемые HTTP-коды (например, `200-399,401`), ключевая фраза, порог «медленно», метод/заголовки/тело запроса — у каждого сайта свои ручки.
- **📤 Экспорт / 📥 импорт** — список сайтов со всеми настройками одним JSON-файлом: переезд между инстансами или просто копия.
- **👀 «Видел, не напоминать 2 ч»** — на эскалирующем инциденте: глушит повторы, не закрывая инцидент.
- **🔧 Тех. окна** — регулярные расписания («будни 02:00–04:00», можно через полночь) на сайт или на всё сразу: алерты и эскалация молчат, проверки и статистика продолжаются.
- **💓 Heartbeat-джобы** — добавляются из чата, бот выдаёт готовую строку `curl` для крона.
- **⏸ Пауза сайта** — деплоишь большое? Поставь алерты на паузу на час или до утра; проверки продолжаются молча.
- **🌐 Публичная статус-страница** — один переключатель поднимает страницу в духе Uptime Kuma на `/status` (текущий статус, uptime 24ч/7д/30д/90д, обезличенная история инцидентов, баннер тех. работ), её JSON-двойник `/status.json` для своих дашбордов и SVG-бейджи аптайма для README. По умолчанию выключена; секретный slug делает ссылку приватной.
- **🩺 Диагностика как чеклист настройки** — три группы: работает / требует внимания / можно подключить. У каждой не-зелёной строки кнопка: либо чинит на месте (включить статус-страницу, сгенерировать heartbeat-секрет, включить вторую точку), либо открывает мастер из двух-трёх шагов. Google Search Console, Яндекс.Вебмастер и Cloudflare подключаются **из чата**: пришли токен или JSON-ключ, бот проверит живым запросом и сохранит. `.env` остаётся запасным вариантом; неприменимые строки (docker socket на Railway) скрываются, а публичный адрес подхватывается из домена Railway сам.
- **🔔 Тест алерта** — увидь, как выглядит критическое уведомление, до того как оно понадобится.

### 💓 Dead-man switch
Крон бэкапа не может сообщить, что он *не* отработал. Добавь джобу в чате («📋 Ещё» → «💓 Heartbeats») — бот выдаст готовую строку для крона:

```bash
curl -fsS https://your-server:8080/api/heartbeat/<секрет>/backup
```

…и бот сам заметит, что джоба молчит дольше положенного. Восстановление объявляется автоматически.

### 📊 Отчёты, уважающие твоё внимание
- **Утренняя сводка** — одно сообщение: статус сайтов, uptime за 7 дней, ближайшие истечения SSL/доменов, статус heartbeat-джоб, диск, SEO. Читается за 10 секунд.
- **Еженедельный отчёт** (воскресенье) — честный uptime за 7/30/90 дней (сырые проверки + ночные агрегаты), инциденты, ASCII-график времени ответа (моноширинный текст, никаких графических библиотек), метрики Google/Яндекса неделя-к-неделе и состояние собственных зависимостей бота.
- **Тихие часы** — некритичное ночью копится и приходит утром одним дайджестом. «Сайт лежит» пробивается всегда.
- **Тихая доставка** — информационные сообщения приходят без звука; звонят только критические алерты. Тишина по умолчанию — буквально.
- **Эскалация** — лежащий сайт напоминает о себе каждые 30 минут и игнорирует mute. Мёртвый сайт нельзя забыть (сознательно только доступность — пейджинг каждые полчаса об истекающем сертификате приучил бы игнорировать алерты).
- **Итоги инцидентов** — сообщение о восстановлении содержит длительность и причину: *«✅ Восстановлен · лежал 12 мин (14:03–14:15) · причина: HTTP 502»*.

### 🧹 Обслуживает сам себя
- Старые сырые проверки ночью сворачиваются в дневные агрегаты — SQLite не растёт бесконечно.
- Ночные бэкапы базы с ротацией + еженедельная офф-хост копия прямо в твой Telegram-чат.
- Собственный heartbeat на внешний сторож (healthchecks.io) — кто сторожит сторожа.
- **Сам обновляет зависимости**: Dependabot раз в неделю открывает PR, CI (ruff + pytest + pip-audit) его проверяет, workflow автомержа вливает минорные/патч-обновления, хостинг передеплоит — и бот при следующем старте пишет «🔄 Бот обновился: aiohttp 3.10 → 3.14». Раз в неделю сверяется с PyPI и базой уязвимостей OSV и сообщает, если что-то устарело или уязвимо.
- Секреты заботятся о себе сами: пустой или шаблонный `WEBHOOK_SECRET`/`HEARTBEAT_SECRET` заменяется сгенерированным и хранится в базе. Они всегда разные: секрет виджета публичен по природе (уезжает в браузер), секрет heartbeat — нет.

### 📩 Бонус: виджет обратной связи
Встраиваемый JS-виджет для твоих сайтов — сообщения прилетают в Telegram (на сервере rate limiting и лимиты размера) и остаются в боте («📋 Ещё» → «📩 Обратная связь»). Два режима: плавающая кнопка «⚠️ Проблема?» или `button: false` плюс атрибут `data-devops-feedback` на любой ссылке — классическое «нашли опечатку?» в футере открывает форму с уже подставленным выделенным текстом. Сниппет подключения и заметки про CSP: [docs/SETUP.md](docs/SETUP.md#виджет-обратной-связи-нашли-опечатку).

## Быстрый старт

### Railway (сервер не нужен)

Форкни репозиторий → [Railway](https://railway.com) → **New Project → Deploy from GitHub repo**. Railway сам подхватит `Dockerfile`; дальше:

1. **Variables**: `TELEGRAM_BOT_TOKEN` (от [@BotFather](https://t.me/BotFather)) и `DB_PATH=/app/data/bot.db`. Секреты бот сгенерирует сам при первом старте.
2. **Attach Volume** с mount path `/app/data` — база SQLite должна переживать редеплои.
3. **Settings → Networking → Generate Domain** (порт **8080**), затем `PUBLIC_BASE_URL=https://<твоё-имя>.up.railway.app`.

Подробная инструкция по кликам простым языком: [docs/SETUP.md](docs/SETUP.md).
Заметка: функции с docker-сокетом (автоперезапуск контейнеров, автоочистка диска) актуальны только для своего сервера и на Railway тихо отключаются.

### Свой сервер (Docker Compose)

Нужны: Docker и токен бота от [@BotFather](https://t.me/BotFather).

```bash
git clone https://github.com/morgunovtech/Tofs_DevOps_bot.git
cd Tofs_DevOps_bot
cp .env.example .env
# Заполни ОДНО значение: TELEGRAM_BOT_TOKEN (от @BotFather)
docker compose up -d --build
```

Отправь боту `/start` — первый пользователь становится админом, и бот сам
проведёт через добавление первого сайта. Сайты, время отчётов, тихие часы и
heartbeat-джобы управляются из чата; `.env` нужен только для опциональных
интеграций ниже (задокументированы в [.env.example](.env.example)):

| Что включается | Переменные |
|---|---|
| Кнопка передеплоя + автопередеплой | `DEPLOY_HOOKS`, `AUTO_REDEPLOY` |
| Кнопка сброса кэша Cloudflare | `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ZONE_ID` |
| Dead-man switch | `HEARTBEAT_JOBS` |
| Статус индексации Google | `GSC_SERVICE_ACCOUNT_FILE`, `GSC_PROPERTY` |
| Статус индексации Яндекса | `YANDEX_WEBMASTER_TOKEN` |
| Перезапуск контейнеров / очистка диска | `AUTORESTART_CONTAINERS` + монтирование docker.sock |
| Внешний сторож | `SELF_HEARTBEAT_URL` |

## Архитектура

```
main.py                 точка входа: БД → сервисы → веб-сервер → планировщик → polling
├── monitors/           доступность, ssl, домены (rdap), dns, ссылки, 5xx,
│                       seo/geo, хост — типизированные результаты, общая лестница алертов
├── services/           notifier (единственная дверь для сообщений: приоритеты,
│                       mute, тихие часы, паузы), settings, maintenance, secrets,
│                       runtime (админ), updates (контроль зависимостей),
│                       действия Cloudflare, Docker API, скриншоты, GSC, Яндекс
├── reports/            планировщик (19 джоб), форматтеры, ASCII-недельный отчёт
├── handlers/           по роутеру на экран за одним AdminFilter
├── web/                aiohttp: API фидбека, heartbeat, статус-страница + JSON
│                       + бейджи, виджет; HTML-шаблон в web/templates
├── db/                 aiosqlite, WAL, миграции через PRAGMA user_version,
│                       ретенция, бэкапы
├── utils/              url/текст/время — общие помощники для всего выше
└── tests/              pytest: чистые функции, БД, мониторы против локального
                        HTTP-сервера, правила notifier, веб-эндпоинты, экраны бота
```

Стек: Python 3.12+, [aiogram 3](https://github.com/aiogram/aiogram), aiohttp, APScheduler, SQLite (WAL), `zoneinfo` из stdlib. Внешних систем мониторинга нет — бот и *есть* мониторинг. Графических библиотек тоже нет: графики — моноширинный текст.

Про модель безопасности виджета: «секрет» виджета уезжает каждому посетителю сайта, поэтому endpoint считается публичным — защита строится на rate limiting и жёстких лимитах размера, а не на токене. Именно поэтому у heartbeat-эндпоинта *другой* секрет. Осознанный и задокументированный компромисс для инструмента личного масштаба.

## Разработка

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt -r requirements-dev.txt
ruff check .          # линтер + порядок импортов
pytest -q             # ~70 тестов, без сети и без Telegram
pip-audit -r requirements.txt
```

CI гоняет те же три команды на каждый push и PR (Python 3.12 и 3.13). Dependabot по субботам открывает один сгруппированный PR; `.github/workflows/dependabot-automerge.yml` автоматически вливает минорные и патч-обновления после зелёного CI — включи **Allow auto-merge** в настройках репозитория и защити `main` правилом с обязательной проверкой «lint · test · audit», иначе мерж не будет ждать тестов. Контейнер работает от непривилегированного пользователя; `entrypoint.sh` сначала чинит владельца data-тома.

## Статус

Личный проект: собран для моих сайтов и выложен как есть — без SLA и обещаний по роадмапу. Issues и PR приветствуются — особенно новые мониторы и более умное самолечение.

Назван в честь Тофса — ирландского терьера, который принимает аптайм близко к сердцу.
