# Changelog

Что изменилось для того, кто держит бота. Бот обновляется сам (Dependabot → CI → автомерж → Railway и `:latest`), поэтому здесь только версии с номером; даты — даты мержа. Английские заметки к каждой версии — в [Releases](https://github.com/morgunovtech/Tofs_DevOps_bot/releases).

## 3.4.0 — 2026-11-24

Минорный релиз: бот замечает код, который влит, но не задеплоен, — у API-проверок и у Worker-ов. Новых переменных и прав нет (токен GitHub; для Worker-ов — права Cloudflare из 3.3.0). Адреса API и формат `/status.json` не менялись.

**Код влит, но не задеплоен** (#75)
- Раз в сутки: если ответ API-проверки — JSON с полем `version`, он сравнивается с последним релизом репозитория, у которого `homepage` — хост проверки. Отстаёт дольше суток с выхода релиза — одно 🟠 «API … отстаёт от релиза v2.2.2 уже 3 дн.: отвечает версией 2.2.1» с кнопкой «🔗 Релиз v2.2.2»; ✅, когда догнал.
- Worker на маршруте того же хоста: дата последнего деплоя против последнего коммита в `worker/` репозитория; коммит, который ждёт деплоя дольше суток, — 🟠 «Worker … отстаёт от кода».
- Молчит, когда сравнивать не с чем; лежащий API или неответивший GitHub — не «догнал».

**Исправлено**
- Сверка «без присмотра» (3.3.0) брала `homepage` репозитория, даже когда это чужая страница: у ботов там шаблон Railway, и в воскресенье пришло бы «railway.com без присмотра». Теперь в счёт идут только адреса в зоне, на доменах сайтов из списка и имена на платформах вроде `*.pages.dev`.

**Внутри**
- `monitors/availability.answer_text` — ответ так, как его получает проверка; `phrase_state` теперь стоит на нём. `services.updates.gh_json` стал общим, `github.last_commit_at` читает последний коммит по пути.

## 3.3.0 — 2026-11-24

Минорный релиз: бот сам находит опубликованное, за чем никто не следит, и записи DNS, через которые можно захватить поддомен. Новых переменных нет; токену Cloudflare для этого нужны права Zone → DNS → Read, Zone → Workers Routes → Read и Account → Workers Scripts → Read (без них прежнее работает, а бот называет, чего не смог прочитать). Адреса API и формат `/status.json` не менялись.

**Что опубликовано, но не под присмотром** (#74)
- Раз в сутки и перед воскресным отчётом список сайтов и API-проверок сверяется с проксированными записями DNS зоны и CNAME на хостинги, доменами проектов Pages, маршрутами Worker-ов и полем `homepage` репозиториев на GitHub.
- В воскресенье — «🟠 N адресов без присмотра: …» с кнопками «➕ Следить: …» и «Не надо». «➕ Следить» добавляет сайт, как «➕ Добавить»; у маршрута Worker-а бот просит адрес API. «Не надо» запоминается.

**Висячие записи DNS** (#74)
- По всей зоне: CNAME на проект `*.pages.dev` или Worker, которых нет в аккаунте, на имя платформы, которого больше нет, или на несуществующий домен — 🔴 сразу «… можно захватить» с кнопкой «🔗 DNS в Cloudflare», один раз; ✅, когда запись убрали или починили.
- В воскресенье 🟠: CNAME, которые ведут в никуда, и подтверждения и DKIM почтовых сервисов, которых больше нет в MX и SPF (`apple-domain=…`, `zoho-verification=…`, `sig1._domainkey`, …) — «можно удалить».
- Чего не удалось прочитать, названо строкой «⚠️ Не прочитал …: токену не хватает права …».

**Внутри**
- `handlers/sites.add_site` — добавление сайта из «➕ Добавить» и из «➕ Следить» одним путём. `monitors/mail_checker.Provider.verify` — TXT-подтверждения почтовых сервисов. `github.published_repos()` — репозитории с `homepage` и последним релизом.

## 3.2.0 — 2026-11-24

Минорный релиз: бот читает журнал изменений аккаунта Cloudflare и называет причину короткого простоя. Новых переменных нет; токену Cloudflare для этого нужны права Account → Account Settings → Read и Account → Cloudflare Pages → Read (без них всё прежнее работает, а бот один раз назовёт недостающее право). Адреса API и формат `/status.json` не менялись.

**Журнал Cloudflare** (#73)
- Каждые 15 минут бот читает журнал аудита аккаунта (Audit Logs v2). Сразу 🔴 со звонком: удалена запись DNS, сменили DNSSEC или NS-серверы, режим SSL переключили на Flexible или Off, удалили правило переадресации, создан новый API-токен, вход с нового адреса. В тревоге — кто и откуда, что делать, кнопки «✅ Это я», «🔗 Журнал в Cloudflare», «🔗 API-токены». «✅ Это я» запоминает адрес: изменения с него дальше только в списке.
- Утренняя сводка: «☁️ Cloudflare за сутки: N изменений» и кнопка «📋 Что изменилось». Тихий день — строки нет.
- Первое чтение только запоминает адреса последних суток. Чтения, неудачные попытки и входы не считаются изменениями. Отказ Cloudflare называет недостающее право — одним 🟠 и строкой в «🔌 Подключения».

**Причина короткого простоя** (#73)
- В тревоге «не открывается» и в «✅ снова открывается» — «Рядом по времени: деплой Cloudflare Pages 7991da4 в 14:02», если за 10 минут до первой неудачной проверки был деплой проекта Pages этого адреса или изменение в зоне. Позже минуты после неё — уже починка, не причина. На поиск — не больше 8 секунд.

**Внутри**
- Общий клиент Cloudflare `services/cloudflare.py`; `services/actions.py` (сброс кэша, проверка токена) перешёл на него, его прежние `CF_API`, `_cf_json`, `_cf_error` удалены.

## 3.1.0 — 2026-11-24

Минорный релиз: обновление, которое само сдвинуло поведение бота, говорит об этом один раз. Переменные `.env`, адреса API и формат `/status.json` не менялись.

**Обновление поменяло поведение — сказать один раз** (#72, `~/BOT_PRINCIPLES.md` §6)
- При каждом старте бот записывает, как он работает: часы и пояс сводок, тихие часы, «будить только когда сайт лёг», все ручки «🛠 Тонкие настройки», язык, что делает сам (пересборка, перезапуск, очистка диска), вторая точка, скорость из региона, воскресная копия, статус-страница — и рядом то, что задал владелец: значение из чата и переменные `.env`.
- Если значение сдвинулось, а чат и `.env` те же, его сдвинул новый код — другое умолчание, другая граница, пояс, зависящий от языка. Тогда одно тихое «ℹ️ После обновления я работаю иначе…» со строками вроде «утренняя сводка: 08:00 (было 09:00)» и кнопкой на экран, где это меняется. Поменянное в чате или в `.env` — не новость; первый старт только записывает; сообщение, которое не ушло, повторится при следующем старте.

## 2.2.0 — 2026-11-24

Минорный релиз: чужой текст больше не рисует экран владельца, `/restore` работает как команда, сообщения бота называют экраны так, как они подписаны. Новое — только псевдоним `/restore`, совместимый с прежним поведением; переменные `.env`, адреса API и формат `/status.json` не менялись.

**Безопасность текста и восстановление** (#55)
- **Чужой текст не рисует экран.** Направляющие и невидимые символы (U+202A–U+202E, U+2066–U+2069, U+200B–U+200F, U+2060–U+2064, BOM, управляющие) вырезаются из всего, что бот показывает (`clean()` внутри `esc()`): заголовок страницы или сообщение виджета больше не может перевернуть строку («exe.png» → «gnp.exe»). Ссылки в сообщениях виджета обезвреживаются (`hxxps://evil[.]example/x`) — и в тревоге, и на экране «📩 Сообщения с сайтов»: в чат владельца не приходит кликабельная чужая ссылка.
- **`/restore` как псевдоним.** Ответ `/restore` на сообщение с копией базы делает то же, что и сам файл; `/restore` без файла объясняет, что прислать.

**Старые названия экранов в сообщениях бота** (#67)
- Сообщение «📩 Виджет обратной связи обновился…» ведёт к «⚙️ Настройки → 🌍 Для посетителей → 📩 Подключить виджет» (было несуществующее «📩 Обратная связь»); ответ на паузу автодействий («⏸ Ничего не делаю сам…») и мастер Cloudflare называют экран «🤖 Что делаю сам», как он подписан (было «🤖 Что бот делает сам»). Тест в `tests/test_docs.py` следит, чтобы старые названия не вернулись ни в русские тексты, ни в английские.
- Убраны неиспользуемые английские переводы прежних экранов «⚙️ Настройки» и «🔔 Когда писать» и кнопки «🗄 Копия базы по воскресеньям».
- Прежние адреса бейджей `/status/badge/…` работают до следующего мажорного релиза (3.0.0) — так и сказано в `docs/FEATURES.md`.

Выбранное в чате главнее `.env`, переживает перезапуск (`cfg:*` в `bot_state`, уезжает с копией базы) и применяется сразу: обход ссылок перепланируется, язык переключает каждый экран и присылает новые кнопки под полем ввода (старые русские подписи при этом продолжают работать). На том же экране — что меняется только на сервере, с именем переменной. Все читатели этих значений — планировщик, мониторы, недельный отчёт, статус-страница, экраны — ходят через `services.settings`, а не `config`; границы значений общие для `.env`, кнопок и восстановленной копии (`utils/validate.py`).

**Код-ревью: доставка тревог, секреты, кнопки, английский** (#62)
- Тревога доходит, когда базе плохо: просроченная пауза «🔧 Я чиню» и отметка «когда задача добавлена» больше не роняют доставку при отказе записи (полный диск); отметка `last_run` и `morning_sent_at` после отправленной сводки — тоже, вместо ложного «сломалась» и повторной сводки после рестарта.
- Тревога, которую Telegram не принял (бот заблокирован, владельца ещё нет, текст отвергнут), не считается сказанной: инцидент остаётся в долгу и досылается через полчаса, а не каждую минуту. Кнопка, которую Telegram не принимает (чужая ссылка), не теряет сообщение — третья попытка уходит без кнопок и говорит об этом.
- Смена A/AAAA, тревога о которой не ушла, повторяется на следующем часу: новые адреса попадают в пул только через закоммиченный baseline.
- Помощники слышат о сайтах, которые добавились в групповую тревогу или в групповое ✅ правкой сообщения; сбой догоняющего запуска (`catchup:`) приходит владельцу как сбой самой задачи; сводка виджета не теряет счётчики при неудачной отправке.
- Секреты: адрес API-монитора с похожим на ключ сегментом пути (`/bot123…:AAF…/getMe`, `/hooks/<ключ>`) не уходит на check-host; при импорте и восстановлении копии сайты названы по метке, без query; ключ сервиса снимков и параметры вида `access_key=`, `auth_token=`, `x_api_key=` маскируются в логах; строки лога проверок — без query.
- Граница доверия для адресов внутри сети — домен владельца, а не любое имя под общим доменом: `evil.duckdns.org` больше не считается тем же сайтом, что `me.duckdns.org` (и для ссылок, и для вложенных sitemap).
- Веб-сервер: память «сказано раз в час» ограничена сверху — поток случайных `Origin` не растит процесс; `/start helper_…` с мёртвой ссылкой отвечает незнакомцу раз в десять минут; сообщения виджета на экране «📩 Обратная связь» — одной строкой, как в тревоге.
- Кнопки: «🔧 Я чиню» с тревоги и пауза с карточки сначала отвечают на нажатие и ничего не делают для нажатия из очереди после рестарта; экран ошибки гасит «часики» на кнопке; «Не предлагать» под старой подсказкой переживает сообщение, которое нельзя править; номера в callback — только ASCII-цифры (`cb_int`); домен, набранный вне мастера (`my-shop-2024.example.com`), не удаляется как ключ; таймаут проверки сертификата назван по имени.
- Английский: «⌛ Это нажатие пришло…» переводится в 22 местах, где уходило по-русски; пометка обрезанного сообщения, отказ «адрес во внутренней сети» и причины CrUX — на языке чата.
- Один прогон проверок открывает не больше 16 соединений разом; страница из sitemap на карточке — без query.

**Английский интерфейс** (#56–#61)
- `BOT_LANG=en` переключает на английский каждый экран, тревогу и отчёт; `ru` по умолчанию, поведение русского бота не изменилось. Русская строка в коде — ключ, английские словари в `locales/en/`, `utils/i18n.py` (`t()`, `plural()`, `fmt_duration()`); `tests/test_i18n.py` рисует каждый экран по-английски и падает на первой кириллической букве.
- Часовой пояс по умолчанию следует языку: `Europe/Moscow` для `ru`, `UTC` для `en` (явный `TIMEZONE` главнее).
- Тексты, которые мониторы кладут в базу как вердикты (стоп-фраза, 5xx на страницах, уровень находки поиска), остаются русскими ключами и переводятся при показе; находки почты, защиты и поиска записываются на языке чата.
